# Vaqrin 语言规范 v0.1.2

**状态：实验性整合规范。** 本文定义 Vaqrin v0.1.2，Vaqrin 源文件使用 `.vqr` 后缀。本版正式采用 `[_]T{...}` 数组长度推断，统一已有值与临时值的所有权规则，并规定错误传播、任务完成和通道交付的时刻。设计讨论中的 v1.17、v1.18 为讨论编号。本规范定义源程序的行为，不规定编译器架构或开发路线。

## 1. 版本与兼容性

语言版本采用主版本、次版本、修订版本。v0 的任意更新均可改变语法或语义。自 v1.0.0 起，同一主版本保证先前合法源码仍可完成词法和语法分析；新增关键字不得破坏原有合法标识符，可以使用上下文关键字。不同主版本可变更语法。此承诺的范围是源代码语法；类型检查、运行行为、标准库 API、ABI、诊断文本和性能如有兼容保证，应另行说明。每个程序按选定的语言版本判断。

## 2. 语言模型与术语

本语言为原生编译、静态强类型、确定性资源管理的通用系统语言。核心机制包括值语义、显式移动、RAII、泛型、组合、编译期计算和可恢复错误。并发设施按目标能力选用。语言允许普通非拥有指针，不要求完整的生命周期或借用检查。

**编译错误**要求静态拒绝。**可恢复错误**是 `!T` 的失败分支。**trap** 是规定的运行期检查失败，终止程序；`panic(message)` 显式触发不可恢复终止。**未定义行为（UB）**表示程序违反了语言交给调用者保证的前提。正常返回或经错误通道退出均按 RAII 清理；trap、panic、进程强制终止和 UB 均无完整清理保证。

## 3. 源码、字面量与标识符

源文件编码为 UTF-8。v0.1.2 的标识符使用 Unicode 17.0 的 XID_Start 与 XID_Continue，首字符另允许下划线；区分大小写，按 NFC 规范化后的序列比较。单独的 `_` 用作模式或解构中的忽略项，以及数组构造中的推断标记。关键字不能作普通标识符。标识符的正规化不影响字符串内容。空白和换行通常只分隔词法单元。`//` 为行注释，`/* ... */` 为不可嵌套块注释。普通声明、赋值、表达式语句用分号结束；以块为主体的声明及控制流语句允许省略末尾分号。列表允许尾逗号。

`#` 引入声明属性，例如 `#copy: enable`、`#implements: Speaker`。属性占独立一行，以换行或分号结束。`@` 保留。整数支持十进制及 `0b`、`0o`、`0x` 前缀，数字间可用下划线分隔，可加位宽后缀，如 `1_000`、`0xff`、`42u64`。浮点可加 `f32`、`f64` 后缀。无其他上下文时整数默认为 i32、浮点默认为 f64。`1..10` 中的两点为范围运算符，小数点后须有数字。

`true`、`false` 为布尔值。`'中'` 是一个 Unicode 标量，`"你好\n"` 是拥有型 UTF-8 文本。标准转义有 `\n`、`\t`、`\\`、`\"`、`\'`、`\u{HEX}`；码点须为合法标量。`null` 需根据预期可空类型解释，`x := null;` 编译错误。

## 4. 包、导入与可见性

同包目录内的源文件以 `package name;` 开头，同包共享包级声明。导入在本文件内有效，可按逻辑路径指定并改别名。包之间禁止循环依赖。

```cpp
package main;
import (geometry, owner/math as omath);
```

使用 `geometry.Point`、`omath.sin(...)` 访问导出符号。默认别名为路径末段，导入不会展开符号。包级声明用 `pub` 导出。类成员用 `public:`、`private:` 分段，默认为私有。项目可以在 `package.toml` 中将逻辑名映射到 Git 依赖或其他来源；锁定文件记录精确版本。

局部名称从内到外查找，再查当前实例成员、当前文件导入、包级及预定义声明；可用 `self.x` 明确选取字段。内层块允许遮蔽，同一块重复声明错误。形参与函数最外层局部同域。导入别名与本文件可见的包级名冲突时须改别名。类型、值及函数在同一声明域中仅可按明定的重载规则重名。包级声明可前向引用，编译期初始化依赖须无环。

包级 `var`、`const` 的初值必须能在编译期确定。v0.1.2 的包级存储只容纳无需运行期析构的值；需要管理的资源可由入口函数持有并显式传入。使用字符串字面量定义包级文本常量允许引用静态不可变数据，其存储期覆盖整个程序，且不需运行期释放。

## 5. 类型、数组与切片

| 拼写 | 值与权限 |
|---|---|
| `bool`、`char` | 布尔值与 Unicode 标量。char 排除代理项 |
| `iN`、`uN` | N 位有符号与无符号整数，N 为正整数。目标公开支持范围，至少支持 8、16、32、64 位 |
| `isize`、`usize` | 目标地址宽度的有符号、无符号整数 |
| `f32`、`f64` | IEEE 754 二进制单精度与双精度 |
| `void`、`type` | void 有唯一普通完成值；type 仅用于编译期的类型值 |
| `string`、`str` | 拥有型不可变 UTF-8 文本、非拥有只读 UTF-8 视图 |
| `[N]T`、`Vec<T>` | 拥有元素的定长数组、可增长顺序容器 |
| `[]T`、`[]const T` | 可修改、只读的非拥有切片 |
| `(A, B)` | 元组，元素位置与类型均参与类型身份 |
| `?T`、`!T` | 可缺失值、可恢复错误结果 |
| `*T`、`*const T` | 非拥有非空指针，分别允许修改、只读 |
| `^T` | 独占拥有指针 Box |
| `func(A, B) R` | 非空的本语言调用约定函数指针 |

前缀构造从右向左结合。`?*T` 和 `?^T` 分别是可空普通指针和可空 Box。`!?T` 的成功载荷为 `?T`，`?!T` 的有值载荷为 `!T`。`!(A, B)` 成功时携带元组。`type Count = u64;` 仅创建别名；需要独立类型时用 class 或 enum。直接按值包含造成无限大小的类型非法；通过指针或 Box 间接递归合法。

```cpp
a := [_]i32{10, 20, 30};          // [3]i32
b := [3]i32{10, 20, 30};          // [3]i32
empty := [_]u8{};                 // [0]u8
rows := [_][2]u8{[2]u8{1, 2}, [2]u8{3, 4}};  // [2][2]u8
```

**`[_]T{...}` 是固定数组构造表达式。** 长度等于最外层初始化元素数，逐元素从左到右在 T 上下文中构造。显式 `[N]T{...}` 必须恰有 N 项；N 为非负编译期整数，布局须适合目标。单独的 `[_]T` 不可用作字段、参数、返回类型或类型别名。运行期变长数据用 Vec，借用任意长度的数据用切片。

下标按元素计数。`a[i]` 要求 `0 <= i < len`，`a[lo..hi]` 要求 `0 <= lo <= hi <= len`，否则 trap。`a[:]` 表示整个范围；只读数组只能形成只读切片。`[0]T` 合法，任何元素下标均越界。索引先按数学值检查，不能把负数截断成合法下标。

## 6. 绑定、表达式与求值

```cpp
var x: i32 = 10;
var y = 20;
z := 30;
const n = calculate();
comptime const width = 16;
```

`var`、局部 `:=` 可重新赋值。元组解构 `q, r := divmod(a, b);` 引入可变局部。`const` 令绑定及内嵌字段、数组元素只读，不可从该绑定移走资源。通过它存放的独立指针或切片访问其他对象时，遵守指针或切片自身的目标权限。函数内 const 允许运行期初值；comptime const 要求编译期求值。

**统一取值规则。** 从具名变量、字段、下标或解引用位置按值取得已有对象时复制；从临时拥有值或显式 `move(x)` 按值取得时交付所有权；取地址和构造视图只借用。实参、返回、尾表达式、字段初始化、赋值、模式绑定及错误或可空解包均适用。不可复制的已有值不能借上述某个位置隐式移出。对只读标量的运算和比较只读取其值，不改变原绑定的有效性。

局部可先写 `var x: T;`。只有所有到达该处的路径均已完整初始化它，才能读、借址或移动。移动后可重新初始化。遇到分支或循环回边时合并状态；再次完整赋值只清理该路径上实际存活的旧值。赋值先定位左侧一次，再求右侧。右侧成功后才替换旧目标；传播错误时已发生的其他副作用保留。

普通操作数、实参按从左到右求值。短路逻辑、可空运算、比较链、选择通信和字段初始化各按专门条文。可执行块为表达式，末项无分号时产生其值；空块或以分号结束的块产生 void。声明体不适用。return 结束最近的函数或 Lambda。return、break、continue 和 panic 对当前表达式均无正常完成值，类型汇合时忽略该路径。

## 7. 运算与数值转换

普通整数 `+`、`-`、`*`、`/`、`%` 及位运算先将小于 32 位的整数提升为 i32，再要求操作数类型相同；未定型整数可适配到确定的运算类型。其他具体整数或浮点类型不得自动混用。整数比较沿用上述匹配。bool 不与整数互转。纯未定型整数常量表达式按数学整数计算，在需要具体类型时检查最终范围；已有类型的运算始终遵守该类型的规则。要求编译期求值的位置若会 trap，则编译错误。

| 运算 | 规则 |
|---|---|
| 有符号加、减、乘、取负、普通左移 | 以运算类型检查数学结果，越界 trap；以二进制补码解释位运算 |
| 无符号普通加、减、乘、左移 | 在运算位宽内回绕 |
| 整数除与余 | 除法向零截断，余数符号跟被除数。零除数 trap。最小有符号数除以 −1 时 trap，对 −1 取余为零 |
| `+%`、`-%`、`*%`、`<<%` | 保留左操作数位宽，回绕 |
| `+\|`、`-\|`、`*\|`、`<<\|` | 保留左操作数位宽，夹到最小或最大值 |
| `>>` | 有符号算术右移，无符号逻辑右移 |
| `&`、`\|`、`^`、`~` | 按位与、或、异或、取反，只接受整数 |
| `!`、`&&`、`\|\|` | 布尔非、短路与、短路或 |
| `==`、`!=`、`<`、`<=`、`>`、`>=` | 相等与顺序比较；顺序链中的中间值只求一次并短路，相等比较不可连写 |

显式回绕和饱和加减乘要求同型整数或可适配常量，不做小整数提升。所有移位的右操作数可为任一整数类型，值必须在零至左侧运算位宽减一之间，否则 trap。普通移位对小整数左侧先提升。浮点操作遵守 IEEE 754，允许 NaN、无穷和有符号零，浮点除零按 IEEE 规则处理；默认不得采用改变这些结果的 fast-math。

`=`、`move=`、复合赋值、`++`、`--` 为语句。复合赋值在左值整数位宽内运算，左侧只求值一次。`++`、`--` 分别等同于 `+= 1`、`-= 1`。回绕和饱和也有对应复合赋值，如 `+%=`、`+|=`、`<<%=`。因此 `u8(250) + u8(10)` 得到 i32 的 260，`x := u8(250); x += 10;` 得到 u8 的 4。

`T(value)` 执行显式转换。类型可覆盖整个源整数值域时返回 T，否则返回 !T；静态已知越界报编译错误。未定型整数字面量直接按 T 构造，故 `i8(7)` 是 i8，`i8(i32(7))` 是 !i8，`i8(128)` 编译错误。浮点到整数以 `truncToInt<T>(x)!`、`roundToInt<T>(x)!` 等函数指定舍入并检查范围、NaN 及无穷。整数到浮点及浮点窄化按目标格式就近舍入，平局取偶。逻辑位宽、存储大小和对齐须分别计算；`bitCast<T>(x)` 限于无填充、存储大小和逻辑位宽相同、目标所有位模式均有效的整数或 IEEE 浮点类型。拥有对象、指针、bool、char 和枚举不在此接口范围内。

## 8. 控制流与迭代

```cpp
best := if (a > b) a else b;
best2 := if a > b { a } else { b };
label := switch code { 0 => "idle", 1, 2 => "running", else => "unknown" };
for i := 0; i < n; i++ { work(i); }
for (i := 0; i < n; i++) { work(i); }
for i < n { work(i); }
for { work(); }
for i, x in enumerate(values) { use(i, x); }
```

条件须为 bool。无括号的 if 条件配块分支，单表达式分支使用括号条件。if 作值时须有 else。switch 判别式求值一次，按源码顺序匹配，无隐式贯穿。作值的 switch 必须穷尽；正常结束的各臂须得出统一类型，允许明定的字面量适配和上下文包装。重复或完全被覆盖的模式非法；同臂各备选模式须绑定同名、同型、同权限的值。break 和 continue 作用于最近的循环，switch 不建立 break 目标。

`a..b` 左闭右开，`a..=b` 为闭区间；端点只求值一次。正向遍历起点大于终点时为空；闭区间到达终点直接结束，包括整数最大值。循环产生 void。`for x in iterable` 构造一个迭代器并反复调用其可变方法 `next() ?Item`，null 时停止。自定义集合以 `iter()` 提供迭代器；元素不可复制时可显式使用返回指针的迭代器。可能失败的迭代器显式调用 `next()!`。`enumerate`、`zip`、`map`、`filter`、`take`、`skip` 为惰性库设施。

## 9. 函数、Lambda 与运算符

```cpp
func add(a, b: i32) i32 { a + b }
func divmod(a, b: i32) (i32, i32) { return a / b, a % b; }
square := (x: i32) i32 => { x * x };
handler := [a, &b, move(c)] (x: i32) i32 => { a + b + x };
```

函数参数按值传递，普通形参形成可变局部。指针形参只复制指针。`return a, b;` 仅在返回语句中简写元组；普通位置写 `(a, b)`。具名值返回遵守复制或显式移动规则。无正常完成值的路径不参与返回类型汇合。`return;` 在 void 或 !void 函数中完成正常返回；函数体自然产生 void 时同理。

Lambda 默认不捕获外层局部。`[a]` 复制，`[&b]` 借用，`[move(c)]` 转移所有权。捕获随闭包按 RAII 释放。引用捕获不延长被引用对象寿命。同型闭包的复制能力取决于全部捕获；需要移动某个拥有捕获的闭包只能消费调用一次。消费调用 `move(f)(args)` 或将闭包交给声明消费它的 API，可将拥有捕获视作本次调用的局部移动源。其余调用按捕获权限读写，引用捕获不能据以移出他人所有的对象。Lambda 有独立的 return 和错误传播边界。参数类型只有在上下文足够时才能省略；独立写 `f := x => x * 2;` 编译错误。命名函数和无捕获、签名匹配的 Lambda 可形成 `func(A, B) R`，有捕获的闭包保留自身类型，可传给泛型函数。

```cpp
class Vec2 {
public:
    var x: f64;
    var y: f64;
    const operator +(other: Self) Self {
        Vec2{ x: x + other.x, y: y + other.y }
    }
}
```

运算符使用 `operator` 声明。v0 允许用户类型以只读接收者重载普通二元算术与比较。比较结果为 bool 或 !bool，比较链每一环必须直接产生 bool。可失败算术应显式处理，如 `(a + b)!`。赋值、地址运算、移动、短路逻辑、后备、可空访问及错误传播均为内建操作。普通实参和运算符右操作数不自动取地址；上例的右形参按值，若改为 `*const Self` 则调用写作 `a + (&b)`。

重载先按可见性、元数、参数类型和接收者权限筛选，完全匹配优先于权限收窄、接口视图转换及上下文包装。无唯一最佳候选时报歧义，包括无类型字面量导致的平局。不能只按返回类型区分重载。用户定义的算术用于复合赋值时，正常结果必须可写回左值；可失败重载须先显式处理错误。

## 10. 类、组合与接口

```cpp
class Point {
    var x: i32;
    var y: i32;
public:
    func init(x, y: i32) : x(x), y(y) {}
    const func getX() i32 { x }
    func setX(value: i32) void { x = value; }
}
```

类是具有值语义的独立类型，没有传统继承。普通方法的 self 为 `*Self`，const 方法为 `*const Self`，对象位置在调用实例方法时可自动作为接收者。`static func` 声明无 self 的关联函数，经类型名调用。字段表达式和初始化按字段声明顺序求值，与初始化列表书写顺序无关。进入主体时所有字段均已构造；构造期间只能读取已完成字段，不得在未完成时使 self 逸出。

`func init(...)` 定义普通构造器；`func init(...) !void` 定义可失败构造器，其 `T(args)` 返回 !T。委托写作 `: self(args...)`，禁止成环。最外层构造成功前对象均视为尚未完成，失败逆序清理已完成字段，不调用整体 deinit；堆构造还须归还对象存储。已在主体获得的资源须由有效字段或局部拥有。当类没有用户构造器、所有字段均可访问且能完整初始化时，允许 `T{field: expr, ...}` 字段构造。用户构造器存在即关闭该入口。

```cpp
interface Speaker {
    const func speak() void;
}
class Dog {
    #implements: Speaker
public:
    embed animal: Animal;
    const func speak() void { animal.speak(); }
}
```

`embed name: Type;` 和 `embed Type;` 都是成员组合，省略名称时以类型最后一个标识符命名。`embed Animal;` 的字段访问为 `dog.Animal.age`。只提升可访问的普通实例方法；字段、构造、copy、clone、deinit 等不提升。提升不能扩大源方法或 embed 声明的可见性。相同参数与接收者签名且结果相同，自身方法优先；结果不兼容在声明处报错。不同签名参与重载，多个 embed 提供同签名且调用仍歧义时，须使用完整成员路径。

类按 `#implements` 显式声明所实现的接口。要求由可见的自身方法或无歧义提升方法满足，签名和权限须匹配。`T: Speaker` 为静态约束。`*const Speaker` 是非拥有的只读动态接口视图；`*Speaker` 可调用可变方法。视图只从仍有效、已实现接口的具体对象指针形成，不延长生命周期。依赖具体 Self 的普通参数或返回类型不能经擦除具体类型的动态视图调用。接口视图的表示不假定与普通 C 指针相同。

## 11. 复制、移动与资源管理

```cpp
a := Type(...);
b := a;                // 复制已有值
c := move(a);          // a 失效
b = c;                 // 复制替换
b move= c;             // 移动替换，c 失效
```

**移动单位。** 普通 `move(x)` 的源为可移动、可变、已完整初始化的具名局部或形参，消费式闭包捕获见 §9。不能直接移走 `obj.field`、`a[i]` 或 `*ptr`。可消费整个枚举或元组后拆出载荷；容器取出与替换接口须维持外部可见对象完整。`x move= y` 与 `x = move(y)` 含义相同。对同一已初始化且具备相应能力的完整绑定，自复制或自移动赋值均为空操作。移动后旧位置不能读取、借址或再次移动，但可完整重建。

**复制控制。** 普通类若无自定义 deinit 且所有字段可复制，默认逐字段复制。`#copy: disabled` 禁止复制。`#copy: enable` 允许以 `const func copy() Self` 自定义复制；否则要求所有字段可复制并逐字段复制。自定义 deinit 的类默认不可复制，启用复制时必须提供 copy。copy 的返回、参数和构造仍须满足一般规则。`const func clone() !Self` 是显式可失败复制接口，不参与隐式复制。数组、元组、可空值、错误结果和带数据枚举的复制能力取决于所有可能拥有的载荷；实际只复制活跃值。

**移动能力。** 移动由语言定义，无用户移动钩子。`#move: disabled` 禁止移动，禁移动字段使其外层按值对象也禁移动。返回或初始化新构造的对象时，在最终位置直接构造，不要求可移动；具名对象仍受取值规则约束。禁复制且禁移动类型不能借覆盖已有活对象来搬迁。对象移走后原对象寿命结束，不能对其执行 deinit。指向旧位置及内嵌字段的指针不会改指新对象。需要稳定地址的对象可禁移动或通过 Box 间接持有。

**析构次序。** 对类先执行本对象 `func deinit() void`，再逆声明顺序释放所有字段与嵌入对象。deinit 不得传播可恢复错误或使对象复活。局部、完整表达式中的临时值、数组元素和元组元素按各自成功构造的逆序清理；已交给外层拥有者的资源按新拥有者的期限清理。构造中途失败只清理已完成部分。返回值先合法构造或交付，然后展开作用域。错误传播、break 及协作取消经正常控制流退出时亦然。

```cpp
box := new Point(1, 2)!;
p := box.asPtr();
box2 := new(pool) Point(3, 4)!;
ptr, ctx := Box.intoRawParts(move(box2));
restored := unsafe { Box<Point>.fromRawParts(ptr, move(ctx)) };
```

`new T(args)` 及 `new(allocator) T(args)` 将分配和构造的失败汇入单层 `!^T`。Box 独占对象和存储，不能复制；Box 本身可移动，即使 T 禁止搬迁，移动 Box 也保持堆中 T 的地址。Box 须保存原分配器或等价释放上下文，并保证其有效期。通用裸地址往返使用上述成对接口，恢复要求正确类型、对齐、原释放上下文及唯一接管。`Box.intoRaw` / `Box<T>.fromRaw` 的仅指针形式限定为默认分配来源；恢复需要 unsafe。自定义分配统一使用 Parts 形式；来源在运行期才确定时，仅指针拆出接口须在拆出前检查默认来源，违反则 trap。`asPtr()` 只提供非拥有指针。

Vec 自身不可复制，可移动，支持显式 `clone()!`（元素需支持相应复制）和 `push(value)!`。可能重排元素的操作要求元素可移动；禁移动元素可经 `Vec<^T>` 持有。缓冲区重分配使原指针和视图失效；即便地址未变，删除的元素、被搬迁的后缀及覆盖这些位置的切片也不能继续使用。追加未重分配且未搬迁原元素时，旧元素位置仍有效，旧切片保留原长度。

## 12. 可空值与文本

`?T` 有 null 与 some(T) 两个分支。`some(expr)` 在预期类型下显式构造一层有值，在模式中解构一层有值。`unwrap()` 遇 null 时 trap。`lhs ?? rhs` 仅在空时求右侧，否则取得内层载荷。`?.` 仅在有值时执行该次成员访问及其调用实参求值，并为结果包一层可空；若字段本身为 ?U，访问类型为 ??U。这保留了“外层对象缺失”和“对象存在、字段缺失”的区别。

具名可空值中的不可复制载荷须通过 `move(opt).unwrap()` 等消费形式取出。非消费匹配可用 `some(&value)` 取得不超过来源权限的指针。嵌套的未定型 null 总是构造预期可空类型的最外层空；要写外层有值、内层空，用 `some(null)`。

string 是拥有型、不可变、有效 UTF-8 的文本。复制可以共享不可变存储，跨线程复制或释放须正确同步。str 是非拥有只读视图，不延长来源寿命。可从 string 借得 str。可变字节经一次验证后仍可能被其他别名改写；要安全地形成持久有效的文本，须复制到不可变存储，或验证并接管独占存储、终止既有可变访问。`byteLen()`、`scalarCount()`、`graphemeCount()` 分别计字节、标量和字素簇。`.chars()`、`.graphemes()` 遍历相应单位，`asBytes()` 返回只读字节视图。无隐式字符下标。文本相等按字节序列，需要规范化时显式调用。可变构建用 StringBuilder。

## 13. 可恢复错误与传播

```cpp
error LookupError { Unavailable }
func lookup(id: i32, available: bool) !?i32 {
    if !available { return LookupError.Unavailable; }
    if id < 0 { return null; }
    id
}
```

error 声明具名成员集合，v0 成员无自定义载荷，身份由包、集合和成员名构成。`!T` 是开放错误域的失败或 T 类型的成功。`!void` 表示可失败且成功无其他信息。返回时先接受与目标同型的结果；对外层 !，具名错误成员产生失败，可构造成成功载荷的值产生成功；对外层 ?，按 §12 构造。可在明确上下文中逐层包装。`ok(expr)` 显式构造一层成功，普通嵌套不会自动展平。`?!T` 的外层空可与内部成功、失败区分。

| `lookup(...)` 的结果 | `lookup(...)!` 的效果 |
|---|---|
| 成功且有值 | 得到 `?i32` 的有值分支 |
| 成功且缺失 | 得到 `?i32` 的 null |
| 失败 | 从最近的可失败函数或 Lambda 提前返回原错误并清理沿途资源 |

`expr!` 只处理外层错误；外围必须具有相应错误通道。`expr catch fallback` 失败时才求后备表达式。`expr catch (err) { ... }` 在分支绑定错误，其正常完成值须能作成功载荷。可在该块中 `return err;`，它返回外围函数。匹配开放错误域须有兜底。具名 `r: !Vec<u8>` 要取得拥有载荷时写 `move(r)!`，函数临时结果可直接写 `makeVec()!`。可存储或原样返回 !T；不允许以普通表达式语句静默丢弃它。调用者可用显式 catch 处理或有意忽略错误。宿主入口返回未处理错误时报告并以失败状态退出。

## 14. 枚举与模式匹配

```cpp
enum Status {
    #repr: u8
    Success = 0, Pending = 1, Failed = 255,
}
enum Message {
    Quit, Text(string), Position(i32, i32), Binary(Vec<u8>),
}
```

枚举为强类型，以 `Type.Member` 或 `Type.Member(args)` 构造，不隐式转整数。默认标签从零开始，显式标签后取其后继；重复或超出指定表示范围编译错误。`#repr: u8` 规定标签类型，并不确定整个带载荷枚举的大小或 C ABI。仅无载荷枚举提供 `fromInt(raw) ?Self`；无对应成员时返回 null。带载荷枚举须同时提供活动成员所需的值。复制、移动和析构均仅作用于活动载荷。

```cpp
switch move(message) {
    Message.Quit => {},
    Message.Text(text) => useText(move(text)),
    Message.Position(x, y) => usePoint(x, y),
    Message.Binary(data) => useBytes(move(data)),
}
```

`switch message` 非消费匹配时，名字按值复制，`&name` 借用；不能复制的载荷可写 `Message.Binary(&data)`。`switch move(message)` 消费整个值，按值绑定交付所选载荷，未交付的资源在分支结束时清理一次。临时判别式至少活到整个匹配结束。模式可嵌套，如 `some(Message.Quit)`。

## 15. 泛型与编译期计算

```cpp
interface Comparable {
    const func greater(other: *const Self) bool;
}
func max<T: Comparable & Copyable>(a, b: T) T {
    if a.greater(&b) { a } else { b }
}
class Holder<T> { var value: T; }
func length<T, comptime N: usize>(a: *const [N]T) usize { N }
func multiply(comptime factor: i32, x: i32) i32 { factor * x }
comptime func square(n: usize) usize { n * n }
comptime const N = square(4);
type Buffer = [N]u8;
```

泛型可用于类、函数和其他允许参数化的声明。`T: I` 要求显式实现 I，`&` 连接多个约束。Copyable、Movable、Sendable、Shareable 为按语言规则判断的内建性质。泛型体须对满足声明约束的类型有效。max 中的 Copyable 使具名 a 或 b 可以作为返回值复制。能唯一确定的实参可推导，否则须显式给出；查找符号后仍有歧义即编译错误。

comptime func 的调用须在编译期完成；普通函数在编译期上下文中，如果所执行的操作均合法，也可求值。已定型表达式遵守相同的数值、错误和权限规则。编译期禁止普通 I/O、网络、FFI、volatile、任务、运行期可变存储访问及向运行期泄露编译期临时地址。type 值可表示已有类型、泛型实例及数组等类型构造；v0 不提供任意匿名类生成。类体中的 `comptime if` 可选择成员。两侧须能解析，每个实例仅选中侧进入成员集并接受依赖实参的语义检查。

## 16. 指针、unsafe 与外部接口

```cpp
p := &value;
*p = 10;
ptr := unsafe { ptrFromInt<*u32>(0x40011010) };
unsafe { volatileStore(ptr, u32(1) << 13); }
```

`*T` 允许别名；`p.field` 可自动解引用。可变指针到只读指针可安全收窄。普通解引用无需 unsafe，但目标须非空、存活、对齐正确、满足类型和范围要求，且访问满足并发合同。无 unsafe 块的程序同样可能因悬垂访问产生 UB。数组下标检查、const 和切片长度都不能维持底层对象存活。

unsafe 块按普通表达式块求值，只对词法范围授权。返回对象不携带该权限。块内 Lambda 的执行体另需自己的 unsafe 块。`unsafe func` 的调用须在 unsafe 环境内，函数体执行危险操作的位置仍须显式使用 unsafe 块。安全封装必须实际维持其所承诺的前提。unsafe 不取消类型、溢出、作用域和析构规则。

| 必须在 unsafe 环境执行的操作 | 调用者的义务 |
|---|---|
| `ptrFromInt`、`ptrCast`、`constCast`、未检查 `ptr.offset(n)` | 确保地址来源、布局、对齐、有效范围及实际可写性。移除只读限定不使只读对象变得可写 |
| Box 的 fromRaw、fromRawParts | 确保正确来源、释放上下文、对象仍存活及唯一接管 |
| 未检查内存访问、`MaybeUninit<T>.assumeInit()` | 空槽不可当 T 读或析构；写入有效对象后，消费槽完成唯一交付 |
| `volatileLoad`、`volatileStore` | 遵守映射、硬件访问宽度、对齐及寄存器的读写权限 |
| 原始外部 C 调用 | 遵守目标 C ABI、参数、回调及内存有效期 |

MaybeUninit 的槽本身不会自动析构其中的 T；重复使用前须正确取出或清理旧值。普通解引用没有 volatile 语义；volatile 保证规定的硬件可观察访问，不提供互斥、原子读改写或线程间屏障。可以在普通包装类中封装具备明确读写权限的 MMIO 操作。

```cpp
extern "C" func puts(s: *const c_char) c_int;
export "C" func callback(value: c_int) void {}
class CPoint {
    #repr: C
public:
    var x: f32;
    var y: f32;
}
```

extern 引入 C 符号；export 按 C 调用约定暴露符号。C 函数指针类型写作 `extern "C" func(A, B) R`，与默认函数指针类型区分。可跨 ABI 的类型限于目标表列出的标量、普通指针、C 调用约定函数指针与递归满足布局条件的 C 聚合。`#repr: C` 按目标 C 布局。`string`、`str` 不隐式转换为以 NUL 结尾的 C 字符串。捕获闭包须显式拆成上下文指针与兼容 C 回调并保证有效期。错误结果与外部异常不能直接跨 ABI 展开。

## 17. 任务并行、Channel 与同步

### 17.1 任务与组

TaskGroup 管理子任务生命周期。`group.spawn(f)` 启动可挂起的任务，返回可失败的任务句柄创建结果。Task 不可复制，可移动。闭包与成功载荷须可跨线程移交；默认拒绝非拥有局部引用捕获。spawn 可消费临时闭包；消费既有不可复制闭包须传 `move(f)`。启动失败不留下子任务，已传入的闭包和捕获由调用清理。若 f 返回普通 T，句柄为 Task<T>；若 f 返回 !T，句柄仍为 Task<T>。join 返回 !T。仅合并任务入口的一层错误，保留 T 内部结构。

**任务完成有确定次序。** 先保存返回值或错误，再清理任务函数局部，再释放入口闭包的剩余捕获，最后发布完成并唤醒等待者。已转移给结果或其他拥有者的资源随新拥有者清理。保留句柄不会延长入口闭包的寿命。

`join()` 通过可变句柄一次取得结果。若调用方等待被取消且尚未取得结果，返回标准任务管理错误 JoinInterrupted，可重试。该成员保留给 join 的等待中断；子任务本身传播了同一成员时，领取其结果仍计为观察，再次 join 返回 AlreadyJoined。若子任务自身以 TaskError.Cancelled 结束，该错误是一次已经观察的结果。完成记录已就绪时优先领取；再次 join 返回 AlreadyJoined。句柄析构不隐式观察结果，也不让子任务脱离组。

`task.cancel()`、`group.cancel()` 请求协作取消。受支持的等待点与 `checkCancelled()!` 可返回取消错误。组析构请求取消未完成任务并等待回收，其回收等待不受自身协作取消打断。忽略取消的任务可使其长期等待。组内任务不得持有本组的生命周期所有权并等待自身退出；可识别的直接自身 join 返回 SelfJoin。组对未被 join 或组级汇总领取的错误逐个报告一次，清理未领取的成功值；没有自定义报告器时使用库的默认报告器。组析构不产生可恢复错误。句柄可移出组并保有独立有效的关闭状态；组关闭后 join 返回 GroupClosed。组回收与结果领取不得对同一记录重复处置。panic 不自动转成任务错误。

任务可并行执行，调度线程无身份稳定保证。支持的 Channel、任务和定时等待只挂起当前轻量任务，核心调用无需 async/await。`parallelMap`、`parallelFor` 等为任务并行库接口。

### 17.2 通道与关闭

`channel.Channel<T>.bounded(n)!` 返回可复制的 Sender<T> 和独占、不可复制的 Receiver<T>；两端都可移动，T 须 Sendable。`bounded(0)` 仅在生产者与消费者配对时交接；正容量通道按消息条数限流；`unbounded()` 可增长，仍可能分配失败。多个 Sender 可并发提交，Receiver 不可并发共享。按提交顺序 FIFO 交付，并发提交可有不同的合法顺序。

| 操作 | 正常与失败行为 |
|---|---|
| `send(value) !void` | 必要时等待。成功后由通道拥有消息；关闭、取消、分配失败时返回对应错误，并清理已取得但未交付的值 |
| `sendPreserving(value) SendResult<T>` | Sent，或 Closed(T)、Cancelled(T)、OutOfMemory(T)；失败处分支交还原值 |
| `trySend(value) TrySendResult<T>` | 立即返回 Sent、Full(T)、Closed(T) 或 OutOfMemory(T) |
| `recv() !?T` | 成功接收消息、关闭排空后的成功 null，或等待取消错误 |
| `tryRecv() TryRecv<T>` | 立即返回 Value(T)、Empty 或 Closed |

调用普通发送方法时，实参照常复制或移动，`send(move(v))` 在进入方法前已使 v 失效。交付成功不保证业务处理完毕。try 操作不另外报告任务取消；零容量时无可配对等待者的 trySend 或 tryRecv 分别返回 Full(原值) 或 Empty，失败尝试不留下待交接消息。

最后一个 Sender 析构或任一 Sender 显式 close 后，所有发送端都拒绝新发送；接收端继续排空，然后返回成功 null。Receiver.close 同样拒绝新发送，并允许该接收者排空。Receiver 析构则一次清理每条未读消息，唤醒等待的发送者。关闭幂等。无论关闭、取消或交付如何竞争，一条消息都只能提交一次。提交完成后到来的取消不能将已交付的消息作为原值退回。

特别地，对 Channel<?i32> 发送 null 后关闭，接收者依次得到成功的 some(null) 和成功的外层 null；被取消的等待经外层错误通道返回。

### 17.3 select

```cpp
event := (select {
    x := dataRx.recv() => Event.Data(x),
    cmd := controlRx.recv() => Event.Command(cmd),
    after(Duration.millis(500)) => Event.Timeout,
})!;
```

select 是识别通道端点操作的表达式。进入时按源码顺序对端点位置和超时参数各求值一次；端点必须保持有效。复杂发送表达式在 select 外求值并绑定。允许发送标量常量、复制无用户代码和可观察副作用的标量局部、显式 `move(完整局部)`；自定义复制可预先取得副本，再将该副本列为 move 来源。等待期间不得通过其他路径移动或改写候选源。相同局部可作为多个互斥发送臂的 move 来源。

**只有成功交付的发送臂才消费来源。** 注册等待、超时、选中其他臂以及交付前发生的关闭、取消或分配失败均保留原值。发送因关闭而就绪时，整个 select 返回错误，不执行该臂的成功主体。接收端关闭且排空时，其 recv 臂持续就绪，可成功取得 null。一次选择至多提交一个操作；同一 select 的两个零容量臂不能彼此配对。

多个就绪臂不能按固定源码首项优先，不承诺单臂在确定期限内获选。无就绪臂时如有 else 则执行，否则挂起。after 从进入时按单调时钟计时，非正时长立即就绪。观察取消发生在提交前可返回错误；已提交后不回滚。select 的类型为 !R，R 为各正常完成分支的统一类型。接收绑定为 ?T，分支主体的 `!`、return 仍作用于外围函数。控制流汇合后，只要有一条正常到达的路径已移走 v，就不能直接读 v。

### 17.4 共享状态和内存顺序

Sendable 表示能在线程间移交，Shareable 表示能按类型合同共享访问。对聚合、容器、枚举、任务结果和闭包，检查全部可能载荷、捕获、分配器状态和析构线程要求。裸指针、非拥有切片、str、非拥有接口视图及引用捕获默认不可跨线程移交；受信任封装须自行保证寿命及同步。只读 string 可移交及共享。`Shared<const T>` 需要允许共享读取的 T，`Shared<Mutex<T>>` 需要可移交给持锁者的 T。共享所有权不授予并发写权限。

Mutex.lock 返回不可复制的 RAII Guard；释放时解锁。`withLock(f)` 在持锁期间调用 f，解锁后不能继续把内部视图当作受该次锁保护。要求原线程解锁的 Guard 须在同一线程释放，任务运行时应满足其亲和性约束。持锁等待仍可能死锁。

同一任务内的求值顺序，与下表同步关系的传递闭包，构成 happens-before。不同任务或不同 OS 线程对同一位置的冲突访问，如至少一个写、至少一个非原子且没有该顺序，即构成数据竞争，行为未定义。

| 发布 | 与之同步的观察 |
|---|---|
| spawn 发布子任务前的操作 | 子任务开始执行 |
| 子任务发布完成，包括释放捕获 | join 或组回收观察到其完成，包括错误完成 |
| 发送成功提交 | 对应接收交付之后 |
| 发送方向关闭 | 接收观察到关闭且排空 |
| 零容量通道接收方进入配对交接 | 对应发送成功返回 |
| Mutex 解锁 | 同一锁随后成功加锁 |
| 对同一原子变量的 release 写 | 读到该写入的 acquire 读 |

Atomic<T> 支持 relaxed、acquire、release、acq_rel、seq_cst；默认 seq_cst。load 允许 relaxed/acquire/seq_cst，store 允许 relaxed/release/seq_cst，读改写允许全部五种。每个原子对象有统一的修改顺序，seq_cst 操作另有共同全序。比较交换失败是读；v0.1.2 允许的（成功→失败）搭配为：relaxed→relaxed；acquire→relaxed/acquire；release→relaxed；acq_rel→relaxed/acquire；seq_cst→relaxed/acquire/seq_cst。volatile 不能替代同步。更完整的原子公理、栅栏及平台支持范围归内存模型和目标附录。

## 19. 综合示例

本例采用宿主并发库。io.println 在此宿主接口中返回 !void，使输出失败也能沿任务错误通道报告。

```cpp
package main;
import (io, task, channel);

enum Work {
    Number(i32),
    Stop,
}

func calculate(n: i32) i32 { n * n }

func main() !void {
    tx, rx := channel.Channel<Work>.bounded(8)!;
    group := task.TaskGroup();

    producer := group.spawn([move(tx)] () !void => {
        for n in 0..10 {
            tx.send(Work.Number(n))!;
        }
    })!;

    consumer := group.spawn([move(rx)] () !void => {
        for {
            msg := rx.recv()!;
            switch msg {
                null => break,
                some(Work.Number(n)) => io.println(calculate(n))!,
                some(Work.Stop) => break,
            }
        }
    })!;

    producer.join()!;
    consumer.join()!;
}
```

生产者移入唯一 Sender 顺序发送十条消息。它退出时先释放捕获，因此即使 producer 句柄仍存活，消费者也能排空并观察到 null。若第二次 spawn 失败，启动调用释放已经转入的 Receiver，生产者的等待发送被唤醒；入口传播错误时组仍取消并回收生产者。若输出失败，消费者退出并释放 Receiver，生产者不会永久等待容量；组分别处理已领取及未观察到的任务结果。

## 20. 规范边界

OS 线程可通过目标的线程库使用，同样遵守 §17 的内存与同步规则。本版不引入传统类继承、字段自动提升、GC、强制借用生命周期标注、自定义移动钩子、任意隐式用户转换、捕获式异常、任意编译期匿名类、内建 actor 或强制 async/await。select 的语法和取值规则属核心，端点及等待能力由可选并发库提供；缺少相关目标能力时使用该设施应得到静态诊断。

本文件可独立阅读，定位为实验性核心规范。完整 EBNF、标准库接口全集、完整原子内存模型、各目标的 ABI 与布局表仍属后续附录。宿主配置规定入口和错误退出；裸机配置规定入口、分配器、trap 处理及可用原子能力。源文件后缀、正式语言名称、包下载实现和调度算法不影响上述源程序规则。
