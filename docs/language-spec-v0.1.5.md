# Vaqrin 语言规范 v0.1.5

本文定义 Vaqrin 的当前语义。编译器命令为 `vaqc`，源码扩展名为 `.vqr`。本版增加后缀空值传播与调试解包诊断，沿用独立的借用引用类型。暂不支持的安全引用组合见 §20。

## 1. 版本与兼容性

语言版本采用主版本、次版本、修订版本。v0 的任意更新均可改变语法或语义。自 v1.0.0 起，同一主版本保证先前合法源码仍可完成词法和语法分析；新增关键字不得破坏原有合法标识符，可以使用上下文关键字。不同主版本可变更语法。此承诺的范围是源代码语法；类型检查、运行行为、标准库 API、ABI、诊断文本和性能如有兼容保证，应另行说明。每个程序按选定的语言版本判断。

## 2. 语言模型与术语

本语言为原生编译、静态强类型、确定性资源管理的通用系统语言。核心机制包括值语义、显式移动、RAII、泛型、组合、编译期计算和可恢复错误。并发设施按目标能力选用。语言允许普通非拥有裸指针及受静态生命周期检查的引用。

**编译错误**要求静态拒绝。**可恢复错误**是 `!T` 的失败分支。**trap** 是规定的运行期检查失败，终止程序；`panic(message)` 显式触发不可恢复终止。**未定义行为（UB）**表示程序违反了语言交给调用者保证的前提。正常返回或经错误通道退出均按 RAII 清理；trap、panic、进程强制终止和 UB 均无完整清理保证。

## 3. 源码、字面量与标识符

源文件编码为 UTF-8。v0.1.5 的标识符使用 Unicode 17.0 的 XID_Start 与 XID_Continue，首字符另允许下划线；区分大小写，按 NFC 规范化后的序列比较。单独的 `_` 用作模式或解构中的忽略项，以及数组构造中的推断标记。关键字不能作普通标识符。标识符的正规化不影响字符串内容。空白和换行通常只分隔词法单元。`package` 和 `import` 为按专用文法读取的文件头部指令，**不使用行尾分号**，也不引入通用自动分号插入。`//` 为行注释，`/* ... */` 为不可嵌套块注释。除 `package` / `import` 头部指令外，普通声明、赋值、表达式语句用分号结束；以块为主体的声明及控制流语句允许省略末尾分号。列表允许尾逗号。

`#` 引入声明属性，例如 `#copy: enable`、`#implements: Speaker`。属性占独立一行，以换行或分号结束。`@` 保留。整数支持十进制及 `0b`、`0o`、`0x` 前缀，数字间可用下划线分隔，可加位宽后缀，如 `1_000`、`0xff`、`42u64`。浮点可加 `f32`、`f64` 后缀。无其他上下文时整数默认为 i32、浮点默认为 f64。`1..10` 中的两点为范围运算符，小数点后须有数字。

`true`、`false` 为布尔值。`'中'` 是一个 Unicode 标量，`"你好\n"` 是拥有型 UTF-8 文本。标准转义有 `\n`、`\r`、`\t`、`\\`、`\"`、`\'`、`\u{HEX}`；码点须为合法标量。`null` 需根据预期可空类型解释，`x := null;` 编译错误。

## 4. 包、源文件、导入与程序入口

### 4.1 文件头部：可选 package 与无分号 import

单个 `.vqr` 源文件可以独立构成可编译程序，**不要求声明 `package`，也不要求具有 `package.toml`**。显式包的文件可以在头部使用 `package Name`；导入写作 `import (path, path as alias)`。**这两类头部指令均不写末尾 `;`**；文件中的其他声明和表达式语句仍遵守其自身分号规则。

```cpp
package demo
import (coll, io)

func main() !void {
    io.println("Hello")!;
}
```

省略包名时也可直接写：

```cpp
import (io)

func main() !void {
    io.println("single file")!;
}
```

文件头部的固定顺序是：至多一个 `package`，然后零个或多个 `import`，然后声明。`package` 仅接受一个标识符，`import` 在匹配的 `)` 后结束；解析通过这些语法边界识别结束，不依靠换行，也不让换行成为普通语句终止符。`package demo;`、`import (coll, io);` **在本版是语法错误**，不能把旧尾分号当作空语句吞掉。文件头部不能出现在普通语句或函数体内；在声明后再出现 `package` / `import` 也报错。

导入默认别名是逻辑包路径最后一段，别名由 `as` 指定：`import (geometry, owner/math as omath)`。使用 `geometry.Point` 和 `omath.sin(...)` 访问公开符号；不会自动把包的全部成员展开到当前文件。导入相对源文件路径时使用**带 `.vqr` 扩展名的字符串字面量**，例如 `import ("helpers.vqr" as helpers)` 或 `import ("lib/helper.vqr" as h)`；路径相对包含该 import 的文件解析。文件导入目标必须是未显式声明 `package` 的源文件：同一匿名目录的导入可访问目录可见成员，跨目录导入只能访问其 `pub` 成员；显式有名包必须经逻辑包路径导入。文件导入可以省略 `as`，但前提是目标文件名去除扩展名后是有效且不冲突的标识符。文件路径须规范化到同一物理源文件身份，重复引用只编译一次。导入循环及冲突别名须诊断，不得依赖文件扫描顺序决定结果。

### 4.2 显式包与匿名文件模块

在**显式包模式**下，同一逻辑包的若干文件都写 `package demo`，除特殊入口 `main` 外，它们共享包级声明与相同的重载/重名检查；普通同包非公开声明可以跨文件访问，`pub` 决定是否可跨包导入。无 `package` 头部的文件**不会仅因为位于同一目录就被暗中加入某个有名包**。不同目录的同名显式包不能自行合并，除非工程清单把这些目录声明为同一包的源根。

在**匿名文件模式**下，每个未声明 `package` 的 `.vqr` 文件有独立的**优先本文件名字空间**，同一目录构成一个可自动检索的**匿名目录工作区**。每个文件可以定义自己的 `main`、`solve` 等辅助函数；同名辅助函数存在于不同文件中时，不会仅因此让单文件程序编译失败。本文件查找不到名字时，编译器查询同目录匿名文件的普通顶层声明：若来源唯一，自动引用并将其所属文件加入依赖图；**同目录共享辅助函数不需要写 `pub` 或 `import`**。若多个同目录文件都提供同名顶层符号，即使其参数不同，也不得按遍历顺序或重载推断擅自选择；必须用文件模块名限定或显式文件导入别名。同文件本地声明始终优先于兄弟文件自动发现的声明。

在同一匿名目录工作区内，未标 `pub` 的顶层声明具有**目录内可见性**：允许当前目录中的其他匿名文件直接引用或通过文件别名访问；`pub` 用于向**其他目录或其他逻辑模块**导出。使用文件名去扩展名得到合法且不冲突的标识符时，可以写 `helpers.double(...)`；无法形成有效标识符时，使用 `import ("helpers-1.vqr" as h1)` 明确命名。跨目录显式导入文件时只能访问 `pub` 成员，不能借助相对路径绕过权限。匿名目录工作区不会因为同目录出现有名包文件就与之合并。

同目录自动发现只搜索同一目录、相同匿名文件模式的源文件，不递归搜索子目录，不自动导入有名包。跨目录使用显式文件导入或包导入。包级/文件级名称、文件模块别名、导入别名若有同一使用点的歧义须报错并展示候选路径；不能静默选择某个来源。局部变量/形参和本文件声明按正常词法作用域查找规则优先，文件间自动发现只作为最后的可见源码候选层。显式包之间仍禁止循环导入；同一匿名目录内文件通过先收集声明头支持相互调用和递归，但包级/编译期初始化依赖仍须无环。

### 4.3 每文件主函数与链接符号

一个源文件可以声明**至多一个顶层 `func main()`** 作为该文件的候选程序入口。**同一个 `package demo` 中的多个文件可以各自定义 `main`**；匿名文件模块也一样。文件入口 `main` 天然是文件私有的特殊声明，不进入共享包级符号表或同目录自动发现列表；不能声明为 `pub`，不能被其他源文件通过 `demo.main`、`helpers.main` 访问，不能仅按参数或返回值重载。类里的 `main` 方法只是普通成员方法，不是程序入口。

宿主可执行文件的候选入口签名规定为 `func main() void`、`func main() !void`、`func main() i32` 或 `func main() !i32`，不得带其他形参、泛型形参或调用约定。`i32` 结果作为宿主进程退出状态；错误结果由宿主入口适配层报告并产生非零退出码，`!void` 成功时退出码为零。其他参数读取由 `env` 等标准包接口负责，不隐式在 `main` 传入命令行参数。裸机配置可以通过目标规范或链接脚本指定自有复位入口，此处的宿主 `main` 适配规则不能替代 MCU 启动代码。

编译器以**规范化的包/文件模块身份、工程相对路径和函数名**生成内部符号，为不同文件的 `main` 分配不同的内部身份。只有构建可执行目标时，由驱动为**选中的**源文件生成唯一一个宿主 C ABI 入口适配符号；其他文件的 `main` 不应导出为本次可执行目标的 `main`，更不能成为隐式依赖。若选中依赖图中存在显式 `export "C"` 或用户指定导出名与入口适配符号重名，必须给出链接前冲突诊断；显式 C ABI 导出不采用内部名字改写。此规则同样适用于分别产出多个对象文件后链接的情形。`pub func main` 非法；需要公开可复用功能时另起函数名。

### 4.4 指定文件、多个文件、目录以及工程主文件

`vaqc build path/to/app.vqr` 使用**所指定文件**的 `main` 作为宿主可执行目标入口，不受目录中其他文件的 `main` 影响；`vaqc check path/to/app.vqr` 不要求存在 `main`。`vaqc build app.vqr util.vqr` 中显式列出的文件作为构建源；当只有一个具有合法 `main` 时可直接选用，当多个都有 `main` 时必须提供 `--entry app.vqr`。编译目标为对象文件或库时不要求 `main`，也不创建可执行入口适配层。

`vaqc build path/to/dir` 以该目录作为构建根。如果目录根的 `package.toml` 设置了 `[build] entry = "relative/file.vqr"`，就以该文件为主文件；命令行 `--entry` 可以显式覆盖配置。若无指定入口，编译器扫描构建根下的候选 `.vqr` 文件：**恰好一个合法 `main` 才能自动选用；零个或多个均须报告清楚原因及候选文件，不根据文件名或枚举顺序猜测**。扫描候选入口时不需要完整编译所有不相关的源码文件，不能因旁边另一个尚未参与本次目标的练习程序存在语法错误而拒绝当前目标构建。

**工程配置文件名沿用 `package.toml`**，避免再引入第二套 `project.toml`。最小示例：

```toml
[package]
name = "scratch"
version = "0.1.0"

[build]
entry = "hello.vqr"
```

这里 `[package]` 是项目元信息，**不会强制所有源文件填写 `package scratch`**，也不改变匿名文件模块的作用域规则；仅存在 `[package].name` 不等于创建了一个可按 `import (scratch)` 使用的逻辑源码包。`[build].entry` 必须是构建根内一个现有 `.vqr` 文件的相对路径；路径规范化后不得逃出项目根目录，若需要外部文件须通过显式依赖引入。文件参数比项目默认入口优先，`--entry` 比二者均优先；只要命令行显式列出源文件，`--entry` 必须指向这些列出的源文件之一；目录模式的 `--entry` 则相对目录根解析。项目可以声明包依赖及目标配置，但依赖版本、锁文件和目标选择不得改变本节的入口规则。

以目录构建时默认递归**发现候选入口**，但自动同目录源码引用仍只搜索当前文件的直接同级目录。递归扫描必须跳过构建输出、VCS 元数据、依赖缓存等非项目源码目录，采用确定性排序；发现仅用于列出入口，不等于将所有候选文件编译或链接。跨目录代码必须显式导入。文件编译时如项目清单可用，可复用其依赖/目标设置，但不因为清单指定了另一个主文件而更换当前入口。

### 4.5 按需依赖分析、构建边界和错误

编译器从所选文件、显式输入源及其可达导入和符号引用建立依赖图，按需加载跨文件合法可见的声明（同目录普通声明或跨目录 `pub`）、类型、泛型实例、初始化常量、必要运行时支持和被引用的函数体，然后进行类型检查与 LLVM 代码生成。**未被引用的其他入口文件和辅助函数不因与本次目标同目录而自动参与链接**；必要的声明索引可以遍历候选文件，但未参与构建的源码文件主体内错误不影响该目标。被显式列为编译输入的文件，以及实际参与依赖闭包的文件，仍须通过对应词法、语法和静态语义检查。动态引用、FFI 导出和需保留的资源清理代码必须成为可达性根或显式保留，不能因表面上没有直接调用而错误裁剪。死代码删除与是否跨函数内联属于优化，不改变此可观察语义。

同一物理源通过不同相对路径、符号链接或导入路径再次出现时必须统一模块身份，防止重复编译与重复析构。源文件的私有符号用相对逻辑路径构造稳定链接身份，不依赖机器绝对路径；文件名/Unicode 规范化导致身份重合、同一工程根下归属不唯一、循环包导入、模糊跨文件同名引用、无效入口签名、多个目录候选入口、C ABI 导出重复均须报诊断并提供可操作的候选文件路径。不得使用最后读取的 `main` 覆盖先读取的入口，也不得在有多个候选时悄悄生成其中之一的可执行文件。

### 4.6 可见性与普通名字查找

包级声明的默认权限为包内可见，`pub` 用于跨包访问。匿名目录工作区的普通顶层声明默认仅在本目录内可见，同目录源码可自动发现，`pub` 用于跨目录文件导入或其他包访问。类成员默认 `private`，既允许逐项写 `pub`，也允许使用 **`public:` / `private:` 段落标签**决定其后类成员的默认权限，直至下一个标签或类体结束。`pub` 永远显式授予当前成员公开权限，在 `private:` 段中也生效；在 `public:` 段中可写但冗余。要在 `public:` 段中单独声明私有成员，应先切换到 `private:`，不提供第二套 `priv` 关键字。访问标签只在类体直接成员层合法，不能出现在包级、函数体或接口契约内部；构造器、嵌入字段和被提升的方法依其最终有效可见性判定，不能因嵌入提升扩大原方法的访问权限。`#implements` 等声明属性的类体位置约束不因标签而改变。

```cpp
pub class Counter {
private:
    var value: i32;
public:
    func init(start: i32) : value(start) {}
    const func get() i32 { value }
private:
    pub func reset() void { value = 0; } // 显式 pub 覆盖此段默认私有
}
```

普通名字查找先按局部变量、形参、当前实例可访问成员及本文件普通顶层声明处理；本文件顶层声明与导入别名同名是诊断错误，不按顺序偷偷遮蔽；然后解析有名包共享声明，再尝试匿名同目录的**普通顶层声明**唯一发现，最后查询适用的预定义声明。相同层的候选不唯一则报歧义，同一文件及同一显式包内重复声明非法（允许的函数重载除外）；**匿名目录中跨不同文件的同名声明本身不产生错误，只有实际使用时产生无唯一候选诊断**。包级声明可以前向引用，但编译期初始化依赖必须无环。普通包级 `var` / `const` 初值要求编译期可求，包级存储不要求运行期析构；有运行期资源的对象应由选定入口或其他明确拥有者管理。`string` 静态字面量可以引用整个程序存续期内的不可变数据。

## 5. 类型、数组与切片

| 拼写 | 值与权限 |
|---|---|
| `bool`、`char` | 布尔值与 Unicode 标量。char 排除代理项 |
| `iN`、`uN` | N 位有符号与无符号整数，N 为正整数。目标公开支持范围，至少支持 8、16、32、64 位 |
| `isize`、`usize` | 目标地址宽度的有符号、无符号整数 |
| `f32`、`f64` | IEEE 754 二进制单精度与双精度 |
| `void`、`never`、`type` | void 有唯一普通完成值；never 没有正常值，是不返回路径的底类型；type 仅用于编译期的类型值 |
| `string`、`str` | 拥有型不可变 UTF-8 文本、非拥有只读 UTF-8 视图 |
| `[N]T`、`coll.Vec<T>` | 拥有元素的定长数组、标准包中的可增长顺序容器 |
| `[]T`、`[]const T` | 可修改、只读的非拥有切片 |
| `(A, B)` | 元组，元素位置与类型均参与类型身份 |
| `?T`、`!T` | 可缺失值、可恢复错误结果 |
| `*T`、`*const T` | 非拥有非空指针，分别允许修改、只读 |
| `&T`、`&const T` | 非空、非拥有的可变／只读引用，具有独立类型身份 |
| `^T` | 独占拥有指针 Box |
| `func(A, B) R` | 非空的本语言调用约定函数指针 |

`never` 允许用于函数返回类型，例如 `func abort() never`；`panic`、`return`、`break`、`continue` 所在的不再正常完成路径以 never 参与表达式类型汇合，并可适配任意所需结果类型（因为该路径不会产生值）。`never` 不能构造、赋值为有效值或假装跨 C ABI 返回对象，不得据此绕过正常路径的类型检查。`void` 与 `never` 不等价。

前缀构造从右向左结合。`?*T` 和 `?^T` 分别是可空普通指针和可空 Box。`!?T` 的成功载荷为 `?T`，`?!T` 的有值载荷为 `!T`。`!(A, B)` 成功时携带元组。`type Count = u64;` 仅创建别名；需要独立类型时用 class 或 enum。直接按值包含造成无限大小的类型非法；通过指针或 Box 间接递归合法。

元组使用零基十进制字段，如 `pair.0` 或 `nested.0.1`。下标越界是编译错误。投影沿用原位置的读写权限，元素的移动和复制遵循一般字段规则。指向元组的指针可以直接投影。

```cpp
a := [_]i32{10, 20, 30};          // [3]i32
b := [3]i32{10, 20, 30};          // [3]i32
empty := [_]u8{};                 // [0]u8
rows := [_][2]u8{[2]u8{1, 2}, [2]u8{3, 4}};  // [2][2]u8
```

**`[_]T{...}` 是固定数组构造表达式。** 长度等于最外层初始化元素数，逐元素从左到右在 T 上下文中构造。显式 `[N]T{...}` 必须恰有 N 项；N 为非负编译期整数，布局须适合目标。单独的 `[_]T` 不可用作字段、参数、返回类型或类型别名。运行期变长数据用 `coll.Vec<T>`（标准库类型，**不是语言关键字**；使用时导入 `coll`），借用任意长度的数据用切片。`^T` 是语言的独占拥有指针类型，`core.Box<T>` 只是其标准包别名；不允许把历史的 `core.Vec<T>` 作为正式公开入口。

下标按元素计数。`a[i]` 要求 `0 <= i < len`，`a[lo..hi]` 要求 `0 <= lo <= hi <= len`，否则 trap。`a[:]` 表示整个范围；只读数组只能形成只读切片。`[0]T` 合法，任何元素下标均越界。索引先按数学值检查，不能把负数截断成合法下标。

## 6. 绑定、表达式与求值

```cpp
var x: i32 = 10;
var y = 20;
z := 30;
const n = calculate();
comptime const width = 16;
```

普通 `var` 和局部 `:=` 引入可重新赋值的局部。元组解构 `q, r := divmod(a, b);` 引入可变局部；允许逐项混合普通绑定和解引用绑定，如 `index, &item := pair;`，但输入必须是对应的元组类型，`&item` 对应分量须是可解引用的值。`const` 令普通绑定及内嵌字段、数组元素只读，不可从该绑定移走资源。通过它存放的独立指针或切片访问其他对象时，遵守指针或切片自身的目标权限。函数内 const 允许运行期初值；comptime const 要求编译期求值。

### 6.1 引用和取地址

```vqr
var n = 10;
var p: *i32 = &n;
{
    var &x = p;
    x++;
    x = 20;
}
var ro: &const i32 = p;
```

表达式 `&obj` 始终产生裸指针。通过只读位置取得的类型为 `*const T`。`var &x = p` 和 `&x := p` 求值一次，适用于指针、引用或 Box，解开恰好一层。显式声明 `var x: &T = input` 可借用已有 T 左值，也可适配一层间接对象。已有可变引用可重借用为可变或只读引用；已有只读引用只允许共享重借用。显式引用声明不能借用普通临时值。借用无法证明来源的裸地址须使用 `unsafe` 并保证整个借用范围内地址有效、权限合法。

引用名访问所指对象，赋值修改目标，目标地址在引用的存续期固定。已有对象在值上下文按 T 的 Copyable 规则读取。`move(x)` 对引用别名非法。`&x` 取得裸地址，权限不能放宽。共享引用可以共享访问；可变引用不能通过复制句柄复制权限。拥有 `?&T` 或 `!&T` 的绑定可用 `move` 交付包装值。类型注解写在普通名字上，`var &x: *T = p` 和 `func f(&x: *T)` 均为错误。

借用按词法范围检查。可变借用阻止所有者经其他安全路径读写，共享借用允许共享读取并阻止写入、替换及移动。重借用生效期间，原引用受同样的冲突规则约束。可保存的新引用不得超过来源的作用域。裸指针变量的重赋值不重定向已建立的引用。

**统一取值规则。** 从具名变量、字段、下标或解引用位置按值取得已有对象时复制；从临时拥有值或显式 `move(x)` 按值取得时交付所有权；取地址和构造视图只借用。实参、返回、尾表达式、字段初始化、赋值、模式绑定及错误或可空解包均适用。不可复制的已有值不能借上述某个位置隐式移出。对只读标量的运算和比较只读取其值，不改变原绑定的有效性。

局部可先写 `var x: T;`。只有所有到达该处的路径均已完整初始化它，才能读、借址或移动。移动后可重新初始化。遇到分支或循环回边时合并状态；再次完整赋值只清理该路径上实际存活的旧值。赋值先定位左侧一次，再求右侧。右侧成功后才替换旧目标；传播错误时已发生的其他副作用保留。

普通操作数、实参按从左到右求值。短路逻辑、可空运算、比较链、选择通信和字段初始化各按专门条文。可执行块为表达式，末项无分号时产生其值；空块或以分号结束的块产生 void。声明体不适用。return 结束最近的函数或 Lambda。return、break、continue 和 panic 对当前表达式均无正常完成值，类型汇合时忽略该路径。

## 7. 运算与数值转换

普通整数 `+`、`-`、`*`、`/`、`%` 及位运算先将小于 32 位的整数提升为 i32，再要求操作数类型相同；未定型整数可适配到确定的运算类型。其他具体整数或浮点类型不得自动混用。整数比较沿用上述匹配。bool 不与整数互转。纯未定型整数常量表达式按数学整数计算，在需要具体类型时检查最终范围；已有类型的运算始终遵守该类型的规则。要求编译期求值的位置若会 trap，则编译错误。

| 运算 | 规则 |
|---|---|
| 有符号加、减、乘、取负、普通左移 | 以运算类型检查数学结果，越界 trap；以二进制补码解释位运算 |
| 无符号普通加、减、乘、左移 | 在运算位宽内回绕 |
| 整数除与余 | 除法向零截断，余数符号跟被除数。零除数 trap。最小有符号数除以 −1 时 trap，对 −1 取余为零 |
| `+%`、`-%`、`*%`、`<<%` | 保留左操作数位宽，回绕 |
| `+\|`、`-\|`、`*\|`、`<<\|` | 保留左操作数位宽，夹到最小或最大值 |
| `>>` | 有符号算术右移，无符号逻辑右移 |
| `&`、`\|`、`^`、`~` | 按位与、或、异或、取反，只接受整数 |
| `!`、`&&`、`\|\|` | 布尔非、短路与、短路或 |
| `==`、`!=`、`<`、`<=`、`>`、`>=` | 相等与顺序比较；顺序链中的中间值只求一次并短路，相等比较不可连写 |

显式回绕和饱和加减乘要求同型整数或可适配常量，不做小整数提升。所有移位的右操作数可为任一整数类型，值必须在零至左侧运算位宽减一之间，否则 trap。普通移位对小整数左侧先提升。浮点操作遵守 IEEE 754，允许 NaN、无穷和有符号零，浮点除零按 IEEE 规则处理；默认不得采用改变这些结果的 fast-math。

`=`、复合赋值、`++`、`--` 为语句。`move=` 已删除；移动赋值只写 `target = move(source)`。复合赋值在左值整数位宽内运算，左侧只求值一次。`++`、`--` 分别等同于 `+= 1`、`-= 1`。回绕和饱和也有对应复合赋值，如 `+%=`、`+|=`、`<<%=`。因此 `u8(250) + u8(10)` 得到 i32 的 260，`x := u8(250); x += 10;` 得到 u8 的 4。

`T(value)` 执行显式转换。类型可覆盖整个源整数值域时返回 T，否则返回 !T；静态已知越界报编译错误。未定型整数字面量直接按 T 构造，故 `i8(7)` 是 i8，`i8(i32(7))` 是 !i8，`i8(128)` 编译错误。浮点到整数以 `truncToInt<T>(x)!`、`roundToInt<T>(x)!` 等函数指定舍入并检查范围、NaN 及无穷。整数到浮点及浮点窄化按目标格式就近舍入，平局取偶。逻辑位宽、存储大小和对齐须分别计算；`bitCast<T>(x)` 限于无填充、存储大小和逻辑位宽相同、目标所有位模式均有效的整数或 IEEE 浮点类型。拥有对象、指针、bool、char 和枚举不在此接口范围内。

## 8. 控制流与迭代

```cpp
best := if (a > b) a else b;             // 恢复：单表达式分支
best2 := if a > b { a } else { b };      // 块分支
best3 := if (a > b) { a } else { b };    // 括号只是条件分组
label := switch code { 0 => "idle", 1, 2 => "running", else => "unknown" };
for i := 0; i < n; i++ { work(i); }
for (i := 0; i < n; i++) { work(i); }    // 恢复：带整体括号的三段式头
for i < n { work(i); }
for (i < n) { work(i); }
for { work(); }
for i, x in enumerate(values) { use(i, x); }
for (i, x in enumerate(values)) { use(i, x); }
```

### 8.1 if 两种分支形式

条件必须为 `bool`。原有两种有用途的语法均保留：**块分支**使用 `if cond { ... } else { ... }`，条件可以额外用括号分组；**单表达式分支**使用 `if (cond) expr else expr`，要求条件整体有外层圆括号，以明确条件和非块分支的分界。不允许无括号的 `if cond expr else expr`。单表达式分支必须带 `else`，因为该形式本身是有值表达式，不为无 `else` 单语句形式增加第二种悬垂解释。`else if` 形成右结合的条件链，并按照最邻近未闭合 `if` 处理；同一条 `if` 的两侧直接分支须同为块或同为单表达式；`else if` 是可独立选用形式的嵌套链，必要时以块明确分组。`if` 作值时必须覆盖所有正常路径，正常完成分支的类型须能统一；`if` 作语句时可省略 `else`，但其主体须是块。`return`、`break` 等无正常完成路径可按 `never` 参与类型汇合。

### 8.2 for 的括号是可选的头部包围形式

`for` 同时保留三段式 `for init; condition; update { ... }` 和 `for (init; condition; update) { ... }`，其求值、变量作用域和控制流**完全相同**。`for condition { ... }` / `for (condition) { ... }` 是条件循环；`for pattern in iterable { ... }` / `for (pattern in iterable) { ... }` 是遍历循环；`for { ... }`、`for (;;) { ... }` 是无限循环。只有完整头部可选择添加或去掉一层括号；圆括号不是 `for` 的一部分时仍按普通表达式分组处理。解析器在完整配对的可选头部括号内，按**顶层两个分号**识别三段式，按顶层 `in` 识别遍历式，否则为条件式；嵌套调用或表达式中的括号与分号不得误触发另一种头部。条件为空按 `true` 处理。

`a..b` 左闭右开，`a..=b` 双端闭；端点只求值一次，反向空区间不遍历，闭区间达到最大整数端点时也正确终止。循环整体产生 `void`。三段式初始化语句作用域覆盖循环的条件、更新和循环体，循环完成后不可见；更新在正常完成一轮或执行指向本循环的 `continue` 后运行，`break` 不运行更新。`++`、`--` 可用于语句及更新项，不产生表达式值。

`for x in iterable` 构造一个迭代器，并重复调用其 `next() ?Item`，最外层 `null` 结束。支持不可复制元素的集合可以显式提供指针元素迭代器。可能失败的迭代器应当显式处理 `next()!`，普通 `for` 不吞掉错误。`for &x in iterable` 要求 `Item` 为裸指针、引用或 Box。`x` 每轮借用间接目标，迭代器交付的 Box 在本轮结束时释放；裸指针目标遵守原有有效性合同；`index, &item` 混合绑定要求迭代元素为相应元组。若 Item 本身是 `?*T`，不能隐式消除该空层。`enumerate`、`zip`、`map`、`filter`、`take`、`skip` 属于惰性标准包设施。

### 8.3 switch 作为语句和表达式

`switch` 判别式求值一次，依源码顺序检查模式，无隐式贯穿。用作值的 `switch` 必须穷尽；正常结束的各臂须得出统一类型，允许规定的字面量适配与上下文包装。重复或被完全覆盖的模式非法；同一臂的备选模式必须绑定同名、同型、同权限以及相同的拥有/借用类别。`break` / `continue` 只作用于最近的循环，`switch` 不建立自己的 `break` 目标。载荷匹配、`ref name` 与 `switch move(value)` 的精确规则见 §14。

## 9. 函数、Lambda 与运算符

```cpp
func add(a, b: i32) i32 { a + b }
func divmod(a, b: i32) (i32, i32) { return (a / b, a % b); }
square := (x: i32) i32 => { x * x };
handler := [a, &b, move(c)] (x: i32) i32 => { a + b + x };
```

普通形参按值交付，遵循 Copyable 与 move。裸指针形参只复制地址。Box 形参接管所有权，已有 Box 须显式移动。严格引用形参只能接受已有引用；`&const T` 接受来自 `&T` 的共享重借用，`&T` 只接受可变引用。

```vqr
func readStrict(x: &const i32) i32 { x }
func writeStrict(x: &i32) void { x++; }
func read(x: in &const i32) i32 { x }
```

`in` 只允许修饰参数位置的 `&const T`。函数体使用只读引用，运行时传地址。兼容形参接受同类型引用、直接匹配的 T 左值或临时值、指向 T 的裸指针与拥有 T 的 Box。优先借用直接匹配的对象，间接适配恰好解开一层。适配不复制、不移动 T，不获取可写权限，不调用用户转换。物化临时值活到完整表达式清理，包括经错误退出的路径。在调用期适配未经证明的裸地址时，调用者须保证地址有效，派生的引用不得越过完整表达式。

`func(&const T) R` 与 `func(in &const T) R` 为不同函数类型，直接、间接、接口与 Lambda 调用均保留该契约。不能仅靠 `in` 形成重载。带安全引用返回值的函数指针保留返回来源。唯一引用参数作为默认来源；有多个引用参数时使用 1 基索引，例如 `func(&const i32, &const i32) borrow(2) &const i32`。间接调用的借用寿命由该参数决定，来源不同的函数指针类型不可互换。重载匹配顺序为精确类型、权限收窄、兼容适配。按值候选在精确匹配时优先，等优候选报歧义。泛型适配优先采用实参的直接静态类型，`inspect(p)` 对 `p: *i32` 推导 `T=*i32`，`inspect<i32>(p)` 则借用其目标。已由容器确定的键 K 直接使用 K 的适配规则。

### 9.1 返回引用

```vqr
func identity(x: &const i32) &const i32 { x }
```

单个引用形参可作为默认来源；否则用 `#return_borrow: name` 选择引用形参，或用 `#return_borrow: self` 选择实例接收者。返回路径须匹配选定来源，接口实现须保留接口来源契约。可空或错误包装保留活动引用的来源，缺失或错误分支不产生引用。调用处继承实际来源，临时查询键不限制从容器接收者返回的引用。禁止返回局部对象、临时拥有者或来源未证明的地址。输入为临时值的身份函数可在同一完整表达式使用结果，不可保存到外部。间接引用返回目前缺少来源契约，编译期拒绝。

Lambda 与具名函数共享形参规则。按值捕获复制目标值，移动捕获转移拥有值。已建立的安全引用不能被闭包作为引用捕获保存，仍可复制可复制目标。旧式原始地址捕获依赖原对象寿命，不能从该捕获取得可逃逸的安全引用。安全引用及带引用载荷的值不可在线程间移交。

```cpp
class Vec2 {
    pub var x: f64;
    pub var y: f64;
    pub const operator +(other: Self) Self {
        Vec2{ x: x + other.x, y: y + other.y }
    }
}
```

运算符使用 `operator` 声明。v0 允许用户类型以只读接收者重载普通二元算术与比较。比较结果为 bool 或 !bool，比较链每一环必须直接产生 bool。可失败算术应显式处理，如 `(a + b)!`。赋值、地址运算、移动、短路逻辑、后备、可空访问及错误传播均为内建操作。普通实参和运算符右操作数不自动取地址；上例的右形参按值，若改为 `*const Self` 则调用写作 `a + (&b)`。

重载先按可见性、元数、参数类型和接收者权限筛选，完全匹配优先于权限收窄、接口视图转换及上下文包装。无唯一最佳候选时报歧义，包括无类型字面量导致的平局。不能只按返回类型区分重载。用户定义的算术用于复合赋值时，正常结果必须可写回左值；可失败重载须先显式处理错误。

## 10. 类、组合与接口

```cpp
class Point {
    var x: i32;
    var y: i32;
    pub func init(x, y: i32) : x(x), y(y) {}
    pub const func getX() i32 { x }
    pub func setX(value: i32) void { x = value; }
}
```

类是具有值语义的独立类型，没有传统继承。类体允许 `public:`、`private:` 分段访问标签，同时允许在单个成员前使用 `pub`；有效权限遵守 §4.6。普通方法的 self 为 `*Self`，const 方法为 `*const Self`，对象位置在调用实例方法时可自动作为接收者。`static func` 声明无 self 的关联函数，经类型名调用。字段表达式和初始化按字段声明顺序求值，与初始化列表书写顺序无关。进入主体时所有字段均已构造；构造期间只能读取已完成字段，不得在未完成时使 self 逸出。

`func init(...)` 定义普通构造器；`func init(...) !void` 定义可失败构造器，其 `T(args)` 返回 !T。委托写作 `: self(args...)`，禁止成环。最外层构造成功前对象均视为尚未完成，失败逆序清理已完成字段，不调用整体 deinit；堆构造还须归还对象存储。已在主体获得的资源须由有效字段或局部拥有。当类没有用户构造器、所有字段均可访问且能完整初始化时，允许 `T{field: expr, ...}` 字段构造。用户构造器存在即关闭该入口。

```cpp
interface Speaker {
    const func speak() void;
}
class Dog {
    #implements: Speaker
    embed animal: Animal;
    pub const func speak() void { animal.speak(); }
}
```

`embed name: Type;` 和 `embed Type;` 都是成员组合，省略名称时以类型最后一个标识符命名。`embed Animal;` 的字段访问为 `dog.Animal.age`。只提升可访问的普通实例方法；字段、构造、copy、clone、deinit 等不提升。提升不能扩大源方法或 embed 声明的可见性。相同参数与接收者签名且结果相同，自身方法优先；结果不兼容在声明处报错。不同签名参与重载，多个 embed 提供同签名且调用仍歧义时，须使用完整成员路径。

类按 `#implements` 显式声明所实现的接口。要求由可见的自身方法或无歧义提升方法满足，签名和权限须匹配。`T: Speaker` 为静态约束。`*const Speaker` 是非拥有的只读动态接口视图；`*Speaker` 可调用可变方法。视图只从仍有效、已实现接口的具体对象指针形成，不延长生命周期。依赖具体 Self 的普通参数或返回类型不能经擦除具体类型的动态视图调用。接口视图的表示不假定与普通 C 指针相同。

## 11. 复制、移动与资源管理

```cpp
a := Type(...);
b := a;                // 复制已有值
c := move(a);          // a 失效
b = c;                 // 复制替换
b = move(c);            // 移动替换，c 失效
```

**移动单位。** 普通 `move(x)` 的源为可移动、可变、已完整初始化的**拥有型**具名局部或形参，消费式闭包捕获见 §9。`&name` 绑定的名字不拥有被指对象，因此 `move(name)` 即使字面上是标识符也不允许；通过 `alias = value` 或 `alias = move(owner)` 替换目标，按普通赋值规则执行。不能直接移走 `obj.field`、`a[i]` 或 `*ptr`。可消费整个枚举或元组后拆出载荷；容器取出与替换接口须维持外部可见对象完整。`x move= y` 不再是合法语法，必须写 `x = move(y)`。对同一已初始化且具备相应能力的完整绑定，自复制或自移动赋值均为空操作。移动后旧位置不能读取、借址或再次移动，但可完整重建。

**复制控制。** 普通类若无自定义 deinit 且所有字段可复制，默认逐字段复制。`#copy: disabled` 禁止复制。`#copy: enable` 允许以 `const func copy() Self` 自定义复制；否则要求所有字段可复制并逐字段复制。自定义 deinit 的类默认不可复制，启用复制时必须提供 copy。copy 的返回、参数和构造仍须满足一般规则。`const func clone() !Self` 是显式可失败复制接口，不参与隐式复制。数组、元组、可空值、错误结果和带数据枚举的复制能力取决于所有可能拥有的载荷；实际只复制活跃值。

**移动能力。** 移动由语言定义，无用户移动钩子。`#move: disabled` 禁止移动，禁移动字段使其外层按值对象也禁移动。返回或初始化新构造的对象时，在最终位置直接构造，不要求可移动；具名对象仍受取值规则约束。禁复制且禁移动类型不能借覆盖已有活对象来搬迁。对象移走后原对象寿命结束，不能对其执行 deinit。指向旧位置及内嵌字段的指针不会改指新对象。需要稳定地址的对象可禁移动或通过 Box 间接持有。

**析构次序。** 对类先执行本对象 `func deinit() void`，再逆声明顺序释放所有字段与嵌入对象。deinit 不得传播可恢复错误或使对象复活。局部、完整表达式中的临时值、数组元素和元组元素按各自成功构造的逆序清理；已交给外层拥有者的资源按新拥有者的期限清理。构造中途失败只清理已完成部分。返回值先合法构造或交付，然后展开作用域。错误传播、break 及协作取消经正常控制流退出时亦然。

```cpp
box := new Point(1, 2)!;
p := box.asPtr();
box2 := new(pool) Point(3, 4)!;
ptr, ctx := Box.intoRawParts(move(box2));
restored := unsafe { Box<Point>.fromRawParts(ptr, move(ctx)) };
```

`new T(args)` 及 `new(allocator) T(args)` 将分配和构造的失败汇入单层 `!^T`。Box 独占对象和存储，不能复制；Box 本身可移动，即使 T 禁止搬迁，移动 Box 也保持堆中 T 的地址。Box 须保存原分配器或等价释放上下文，并保证其有效期。通用裸地址往返使用上述成对接口，恢复要求正确类型、对齐、原释放上下文及唯一接管。`Box.intoRaw` / `Box<T>.fromRaw` 的仅指针形式限定为默认分配来源；恢复需要 unsafe。自定义分配统一使用 Parts 形式；来源在运行期才确定时，仅指针拆出接口须在拆出前检查默认来源，违反则 trap。`asPtr()` 只提供非拥有指针。

`coll.Vec` 自身不可复制，可移动，支持显式 `clone()!`（元素需支持相应复制）和 `push(value)!`。可能重排元素的操作要求元素可移动；禁移动元素可经 `coll.Vec<^T>` 持有。缓冲区重分配使原指针和视图失效；即便地址未变，删除的元素、被搬迁的后缀及覆盖这些位置的切片也不能继续使用。追加未重分配且未搬迁原元素时，旧元素位置仍有效，旧切片保留原长度。

## 12. 可空值与文本

`?T` 有 null 与 some(T) 两个分支。`some(expr)` 在预期类型下显式构造一层有值，在模式中解构一层有值。`unwrap()` 遇 null 时 trap。`lhs ?? rhs` 仅在空时求右侧，否则取得内层载荷。`?.` 仅在有值时执行该次成员访问及其调用实参求值，并为结果包一层可空；若字段本身为 ?U，访问类型为 ??U。这保留了“外层对象缺失”和“对象存在、字段缺失”的区别。

后缀 `expr?` 要求操作数为 `?T`，只求值一次，只提取一层。有值时结果为 `T`，为空时从当前函数或 Lambda 提前返回并执行正常 RAII 清理。Lambda 的返回类型需显式声明或由函数类型上下文确定。带返回通道的编译期函数也可传播空值，独立编译期初始化式不能提前返回。

| 外围返回类型 | 空分支 |
|---|---|
| `?U`，含 `?!U` 和 `??U` | 返回最外层 `null` |
| `!?U` | 返回成功的 `null` |
| 普通值、`!U`（U 不是直接 Optional） | 编译错误。缺失若应成为错误，可写 `expr ?? { return LookupError.NotFound; }` |

`expr?` 与 `expr!` 具有相同的后缀优先级。比如 `lookup()!?` 依次传播错误和空值。`??` 与 `?.` 按最长词法匹配，分别用于后备表达式及可空成员访问。`(expr?).field` 先传播再访问成员，`(nested?)?` 可逐层检查。传播后的成功载荷遵循普通类型检查，包装层级不会自动展平。

传播遵守正常的复制、移动和借用来源检查。不可复制的已有载荷须经 `move(expr)?` 显式消费。指针载荷仍为指针，引用载荷保留原来源，临时借用不能借此逃逸。同一参数中的 Optional 或 Result 引用载荷也可作为返回借用来源。

`unwrap()` 对空值执行不可恢复 trap，`catch` 无法捕获。宿主构建使用 `-g` 时，运行时在 trap 前向 stderr 写出文件、行号和函数。普通构建和 freestanding 构建只执行 trap。

`value == null` 和 `value != null` 查询可空值的最外层标签，也允许把 `null` 写在左侧。对已有位置的标签比较无需复制其载荷。

具名可空值中的不可复制载荷须通过 `move(opt).unwrap()` 等消费形式取出。非消费模式 `some(ref value)` 借用有值分支载荷的地址，把 `value` 绑定为**载荷类型 T 的左值别名**，需要原指针时使用表达式 `&value`；它不再把指针直接作为 `value` 的类型。若载荷本来就是 `*U`，`value` 是 `*U` 左值，`&value` 是 `**U`，不会递归解引用。嵌套的未定型 null 总是构造预期可空类型的最外层空；要写外层有值、内层空，用 `some(null)`。

string 是拥有型、不可变、有效 UTF-8 的文本。复制可以共享不可变存储，跨线程复制或释放须正确同步。str 是非拥有只读视图，不延长来源寿命。可从 string 借得 str。可变字节经一次验证后仍可能被其他别名改写；要安全地形成持久有效的文本，须复制到不可变存储，或验证并接管独占存储、终止既有可变访问。`byteLen()`、`scalarCount()`、`graphemeCount()` 分别计字节、标量和字素簇。`.chars()`、`.graphemes()` 遍历相应单位，`asBytes()` 返回只读字节视图。无隐式字符下标。文本相等按字节序列，需要规范化时显式调用。可变构建用 StringBuilder。

## 13. 可恢复错误与传播

```cpp
error LookupError { Unavailable }
func lookup(id: i32, available: bool) !?i32 {
    if !available { return LookupError.Unavailable; }
    if id < 0 { return null; }
    id
}
```

error 声明具名成员集合，v0 成员无自定义载荷，身份由包、集合和成员名构成。`!T` 是开放错误域的失败或 T 类型的成功。`!void` 表示可失败且成功无其他信息。返回时先接受与目标同型的结果；对外层 !，具名错误成员产生失败，可构造成成功载荷的值产生成功；对外层 ?，按 §12 构造。可在明确上下文中逐层包装。`ok(expr)` 显式构造一层成功，普通嵌套不会自动展平。`?!T` 的外层空可与内部成功、失败区分。

| `lookup(...)` 的结果 | `lookup(...)!` 的效果 |
|---|---|
| 成功且有值 | 得到 `?i32` 的有值分支 |
| 成功且缺失 | 得到 `?i32` 的 null |
| 失败 | 从最近的可失败函数或 Lambda 提前返回原错误并清理沿途资源 |

`expr!` 只处理外层错误；外围必须具有相应错误通道。`expr catch fallback` 失败时才求后备表达式。`expr catch (err) { ... }` 在分支绑定错误，其正常完成值须能作成功载荷。可在该块中 `return err;`，它返回外围函数。匹配开放错误域须有兜底。具名 `r: !coll.Vec<u8>` 要取得拥有载荷时写 `move(r)!`，函数临时结果可直接写 `makeVec()!`。可存储或原样返回 !T；不允许以普通表达式语句静默丢弃它。调用者可用显式 catch 处理或有意忽略错误。宿主入口返回未处理错误时报告并以失败状态退出。

## 14. 枚举与模式匹配

```cpp
enum Status {
    #repr: u8
    Success = 0, Pending = 1, Failed = 255,
}
enum Message {
    Quit, Text(string), Position(i32, i32), Binary(coll.Vec<u8>),
}
```

枚举为强类型，以 `Type.Member` 或 `Type.Member(args)` 构造，不隐式转整数。默认标签从零开始，显式标签后取其后继；重复或超出指定表示范围编译错误。`#repr: u8` 规定标签类型，并不确定整个带载荷枚举的大小或 C ABI。仅无载荷枚举提供 `fromInt(raw) ?Self`；无对应成员时返回 null。带载荷枚举须同时提供活动成员所需的值。复制、移动和析构均仅作用于活动载荷。

```cpp
switch move(message) {
    Message.Quit => {},
    Message.Text(text) => useText(move(text)),
    Message.Position(x, y) => usePoint(x, y),
    Message.Binary(data) => useBytes(move(data)),
}
```

### 14.1 判别式拥有权和绑定模式

`switch` 对判别式仅求值一次并匹配活动构造分支。`switch message`、`switch *ptr` 等引用已有存储位置时，匹配器不消费原对象；普通 `Tag(value)` **复制**载荷，若载荷不可 Copyable 则编译错误。`switch move(message)` 消费整个合法拥有型局部，匹配器暂时拥有该值；`switch makeMessage()` 一类拥有型临时结果也由匹配器暂时拥有。对这两类拥有值，普通 `Tag(value)` 从当前活动载荷**移动交付**所有权，`Tag(_)` 表示不交付，由匹配器负责析构余留资源。临时判别式至少活到所有分支尾表达式完成，未交付的资源在分支退出前按 RAII 清理一次；未激活的枚举载荷不会被读取、借用或析构。

`some(x)` 按值绑定活动载荷，非消费位置要求可复制。已有可变引用不能复制。消费式匹配可交付 Box 或可变引用句柄。`some(ref x)` 借用已匹配的载荷槽位，权限继承自槽位。若载荷是 `*i32`，这个模式通过 x 访问槽位里的指针对象。`some(&x)` 则借用载荷指向或拥有的目标，要求裸指针、引用或 Box，恰好解开一层。对 `?*i32`，`some(&x)` 直接访问 `i32`。`?^T` 内的 Box 仍由原位置或消费式匹配器负责清理。两种借用模式均局限于分支，不转移其目标。

### 14.2 嵌套、备选模式与所有权边界

`some(ref value)`、`some(Message.Data(ref data))`、`Tag(a, ref b)`、元组及顶层 `ref name` 都递归适用同一规则：借用的是**该级载荷位置**，`name` 类型是该级载荷类型，不发生隐式可空展开或递归指针解引用。非消费匹配中未被忽略的值模式须能复制；消费式匹配可以转移相应拥有载荷、借用其尚未转移的其它字段；其余载荷只析构一次。对原拥有者位置的非消费借用，不得在别名有效的当前分支中直接 `move` 掉匹配的整个已有对象；经其它未知裸指针破坏该位置仍遵守原指针 UB 合同。

方法调用内隐物化的临时接收者保留到所在完整表达式的结果交付之后。当前编译器对可识别的临时借用拒绝保存或返回，需延长拥有者的生命期。正常结束和可恢复错误返回沿用所有权清理规则。安全引用的跨过程来源按 §9.1 检查。

同一 `switch` 分支允许多个备选模式，但**绑定的名字、可见类型、读写权限、拥有或借用方式**必须全部一致，不能把 `TagA(x)` 和 `TagB(ref x)` 视为相同绑定，即使其可见 T 类型相同。`ref` 只在模式位置且后面有绑定名时具有特殊含义；`some(ref)` 仍可绑定名为 ref 的局部。借用匹配不改变外层 `?T` / `!T` 的结构。退出消费式分支时，匹配器按确切的交付、借用和忽略状态清理余留部分，不能因借用了某载荷就提前析构或重复析构。返回指向临时判别式内部载荷的原始指针不会延长其寿命，使用悬垂地址属于 UB。

模式可嵌套，如 `some(Message.Quit)`，穷尽匹配、被覆盖模式诊断、按源码顺序测试以及无隐式贯穿规则仍以 §8 为准。

## 15. 泛型与编译期计算

```cpp
interface Comparable {
    const func greater(other: *const Self) bool;
}
func max<T: Comparable & Copyable>(a, b: T) T {
    if a.greater(&b) { a } else { b }
}
class Holder<T> { var value: T; }
func length<T, comptime N: usize>(a: *const [N]T) usize { N }
func multiply(comptime factor: i32, x: i32) i32 { factor * x }
comptime func square(n: usize) usize { n * n }
comptime const N = square(4);
type Buffer = [N]u8;
```

泛型可用于类、函数和其他允许参数化的声明。`T: I` 要求显式实现 I，`&` 连接多个约束。Copyable、Movable、Sendable、Shareable 为按语言规则判断的内建性质。泛型体须对满足声明约束的类型有效。max 中的 Copyable 使具名 a 或 b 可以作为返回值复制。能唯一确定的实参可推导，否则须显式给出；查找符号后仍有歧义即编译错误。

comptime func 的调用须在编译期完成；普通函数在编译期上下文中，如果所执行的操作均合法，也可求值。已定型表达式遵守相同的数值、错误和权限规则。编译期禁止普通 I/O、网络、FFI、volatile、任务、运行期可变存储访问及向运行期泄露编译期临时地址。type 值可表示已有类型、泛型实例及数组等类型构造；v0 不提供任意匿名类生成。类体中的 `comptime if` 可选择成员。两侧须能解析，每个实例仅选中侧进入成员集并接受依赖实参的语义检查。

## 16. 指针、unsafe 与外部接口

```cpp
p := &value;
*p = 10;
ptr := unsafe { ptrFromInt<*u32>(0x40011010) };
unsafe { volatileStore(ptr, u32(1) << 13); }
```

`*T` 允许地址别名，点访问解引用一层，可变指针可收窄为只读指针。普通裸指针解引用遵守有效、非空、对齐、类型、范围及并发合同。使用悬垂地址属于 UB。引用拥有独立的类型身份，不能作为 FFI 裸地址、MMIO 地址或执行指针算术。

Box 可通过 `(*box).field`、`box.field`、`box.method()` 或显式引用声明借用内部对象。析构负责析构目标并用保存的释放上下文释放分配。所有权移动保持分配地址稳定。活跃的安全引用阻止移动 Box、替换、销毁或 `intoRaw`。`.asPtr()` 产生裸指针。`^*T` 一次解引用得到 Box 所拥有的指针对象；`&^T` 直接借用 Box 本体；`*^T` 适配为 `&const ^T` 时借用指针所指的 Box。

unsafe 块按普通表达式块求值，只对词法范围授权。返回对象不携带该权限。块内 Lambda 的执行体另需自己的 unsafe 块。`unsafe func` 的调用须在 unsafe 环境内，函数体执行危险操作的位置仍须显式使用 unsafe 块。安全封装必须实际维持其所承诺的前提。unsafe 不取消类型、溢出、作用域和析构规则。

| 必须在 unsafe 环境执行的操作 | 调用者的义务 |
|---|---|
| `ptrFromInt`、`ptrCast`、`constCast`、未检查 `ptr.offset(n)` | 确保地址来源、布局、对齐、有效范围及实际可写性。移除只读限定不使只读对象变得可写 |
| Box 的 fromRaw、fromRawParts | 确保正确来源、释放上下文、对象仍存活及唯一接管 |
| 未检查内存访问、`MaybeUninit<T>.assumeInit()` | 空槽不可当 T 读或析构；写入有效对象后，消费槽完成唯一交付 |
| `volatileLoad`、`volatileStore` | 遵守映射、硬件访问宽度、对齐及寄存器的读写权限 |
| 原始外部 C 调用 | 遵守目标 C ABI、参数、回调及内存有效期 |

MaybeUninit 的槽本身不会自动析构其中的 T；重复使用前须正确取出或清理旧值。普通解引用没有 volatile 语义；volatile 保证规定的硬件可观察访问，不提供互斥、原子读改写或线程间屏障。可以在普通包装类中封装具备明确读写权限的 MMIO 操作。

```cpp
extern "C" func puts(s: *const c_char) c_int;
export "C" func callback(value: c_int) void {}
class CPoint {
    #repr: C
    pub var x: f32;
    pub var y: f32;
}
```

extern 引入 C 符号；export 按 C 调用约定暴露符号。C 函数指针类型写作 `extern "C" func(A, B) R`，与默认函数指针类型区分。可跨 ABI 的类型限于目标表列出的标量、普通指针、C 调用约定函数指针与递归满足布局条件的 C 聚合。`#repr: C` 按目标 C 布局。`string`、`str` 不隐式转换为以 NUL 结尾的 C 字符串。捕获闭包须显式拆成上下文指针与兼容 C 回调并保证有效期。错误结果与外部异常不能直接跨 ABI 展开。

## 17. 任务并行、Channel 与同步

### 17.1 任务与组

TaskGroup 管理子任务生命周期。`group.spawn<T>(f)` 启动可挂起的任务，返回可失败的任务句柄创建结果。Task 不可复制，可移动。闭包与成功载荷须可跨线程移交；默认拒绝非拥有局部引用捕获。先将闭包绑定到局部变量，再以 `move(f)` 移交不可复制的闭包。启动失败不留下子任务，已传入的闭包和捕获由调用清理。若 f 返回普通 T，句柄为 Task<T>；若 f 返回 !T，句柄仍为 Task<T>。join 返回 !T。仅合并任务入口的一层错误，保留 T 内部结构。

**任务完成有确定次序。** 先保存返回值或错误，再清理任务函数局部，再释放入口闭包的剩余捕获，最后发布完成并唤醒等待者。已转移给结果或其他拥有者的资源随新拥有者清理。保留句柄不会延长入口闭包的寿命。

`join()` 通过可变句柄一次取得结果。若调用方等待被取消且尚未取得结果，返回标准任务管理错误 JoinInterrupted，可重试。该成员保留给 join 的等待中断；子任务本身传播了同一成员时，领取其结果仍计为观察，再次 join 返回 AlreadyJoined。若子任务自身以 TaskError.Cancelled 结束，该错误是一次已经观察的结果。完成记录已就绪时优先领取；再次 join 返回 AlreadyJoined。句柄析构不隐式观察结果，也不让子任务脱离组。

`task.cancel()`、`group.cancel()` 请求协作取消。受支持的等待点与 `checkCancelled()!` 可返回取消错误。组析构请求取消未完成任务并等待回收，其回收等待不受自身协作取消打断。忽略取消的任务可使其长期等待。组内任务不得持有本组的生命周期所有权并等待自身退出；可识别的直接自身 join 返回 SelfJoin。组对未被 join 或组级汇总领取的错误逐个报告一次，清理未领取的成功值；没有自定义报告器时使用库的默认报告器。组析构不产生可恢复错误。句柄可移出组并保有独立有效的关闭状态；组关闭后 join 返回 GroupClosed。组回收与结果领取不得对同一记录重复处置。panic 不自动转成任务错误。

任务可并行执行，调度线程无身份稳定保证。支持的 Channel、任务和定时等待只挂起当前轻量任务，核心调用无需 async/await。`parallelMap`、`parallelFor` 等为任务并行库接口。

### 17.2 通道与关闭

`channel.Channel<T>.bounded(n)!` 返回可复制的 Sender<T> 和独占、不可复制的 Receiver<T>；两端都可移动，T 须 Sendable。`bounded(0)` 仅在生产者与消费者配对时交接；正容量通道按消息条数限流；`unbounded()` 可增长，仍可能分配失败。多个 Sender 可并发提交，Receiver 不可并发共享。按提交顺序 FIFO 交付，并发提交可有不同的合法顺序。

| 操作 | 正常与失败行为 |
|---|---|
| `send(value) !void` | 必要时等待。成功后由通道拥有消息；关闭、取消、分配失败时返回对应错误，并清理已取得但未交付的值 |
| `sendPreserving(value) SendResult<T>` | Sent，或 Closed(T)、Cancelled(T)、OutOfMemory(T)；失败处分支交还原值 |
| `trySend(value) TrySendResult<T>` | 立即返回 Sent、Full(T)、Closed(T) 或 OutOfMemory(T) |
| `recv() !?T` | 成功接收消息、关闭排空后的成功 null，或等待取消错误 |
| `tryRecv() TryRecv<T>` | 立即返回 Value(T)、Empty 或 Closed |

调用普通发送方法时，实参照常复制或移动，`send(move(v))` 在进入方法前已使 v 失效。交付成功不保证业务处理完毕。try 操作不另外报告任务取消；零容量时无可配对等待者的 trySend 或 tryRecv 分别返回 Full(原值) 或 Empty，失败尝试不留下待交接消息。

最后一个 Sender 析构或任一 Sender 显式 close 后，所有发送端都拒绝新发送；接收端继续排空，然后返回成功 null。Receiver.close 同样拒绝新发送，并允许该接收者排空。Receiver 析构则一次清理每条未读消息，唤醒等待的发送者。关闭幂等。无论关闭、取消或交付如何竞争，一条消息都只能提交一次。提交完成后到来的取消不能将已交付的消息作为原值退回。

特别地，对 Channel<?i32> 发送 null 后关闭，接收者依次得到成功的 some(null) 和成功的外层 null；被取消的等待经外层错误通道返回。

### 17.3 select

```cpp
event := (select {
    x := dataRx.recv() => Event.Data(x),
    cmd := controlRx.recv() => Event.Command(cmd),
    after(Duration.millis(500)) => Event.Timeout,
})!;
```

select 是识别通道端点操作的表达式。进入时按源码顺序对端点位置和超时参数各求值一次；端点必须保持有效。复杂发送表达式在 select 外求值并绑定。允许发送标量常量、复制无用户代码和可观察副作用的标量局部、显式 `move(完整局部)`；自定义复制可预先取得副本，再将该副本列为 move 来源。等待期间不得通过其他路径移动或改写候选源。相同局部可作为多个互斥发送臂的 move 来源。

**只有成功交付的发送臂才消费来源。** 注册等待、超时、选中其他臂以及交付前发生的关闭、取消或分配失败均保留原值。发送因关闭而就绪时，整个 select 返回错误，不执行该臂的成功主体。接收端关闭且排空时，其 recv 臂持续就绪，可成功取得 null。一次选择至多提交一个操作；同一 select 的两个零容量臂不能彼此配对。

多个就绪臂不能按固定源码首项优先，不承诺单臂在确定期限内获选。无就绪臂时如有 else 则执行，否则挂起。after 从进入时按单调时钟计时，非正时长立即就绪。观察取消发生在提交前可返回错误；已提交后不回滚。select 的类型为 !R，R 为各正常完成分支的统一类型。接收绑定为 ?T，分支主体的 `!`、return 仍作用于外围函数。控制流汇合后，只要有一条正常到达的路径已移走 v，就不能直接读 v。

### 17.4 共享状态和内存顺序

Sendable 表示能在线程间移交，Shareable 表示能按类型合同共享访问。对聚合、容器、枚举、任务结果和闭包，检查全部可能载荷、捕获、分配器状态和析构线程要求。裸指针、非拥有切片、str、非拥有接口视图及引用捕获默认不可跨线程移交；受信任封装须自行保证寿命及同步。只读 string 可移交及共享。`Shared<const T>` 需要允许共享读取的 T，`Shared<Mutex<T>>` 需要可移交给持锁者的 T。共享所有权不授予并发写权限。

Mutex.lock 返回不可复制的 RAII Guard；释放时解锁。`withLock(f)` 在持锁期间调用 f，解锁后不能继续把内部视图当作受该次锁保护。要求原线程解锁的 Guard 须在同一线程释放，任务运行时应满足其亲和性约束。持锁等待仍可能死锁。

同一任务内的求值顺序，与下表同步关系的传递闭包，构成 happens-before。不同任务或不同 OS 线程对同一位置的冲突访问，如至少一个写、至少一个非原子且没有该顺序，即构成数据竞争，行为未定义。

| 发布 | 与之同步的观察 |
|---|---|
| spawn 发布子任务前的操作 | 子任务开始执行 |
| 子任务发布完成，包括释放捕获 | join 或组回收观察到其完成，包括错误完成 |
| 发送成功提交 | 对应接收交付之后 |
| 发送方向关闭 | 接收观察到关闭且排空 |
| 零容量通道接收方进入配对交接 | 对应发送成功返回 |
| Mutex 解锁 | 同一锁随后成功加锁 |
| 对同一原子变量的 release 写 | 读到该写入的 acquire 读 |

Atomic<T> 支持 relaxed、acquire、release、acq_rel、seq_cst；默认 seq_cst。load 允许 relaxed/acquire/seq_cst，store 允许 relaxed/release/seq_cst，读改写允许全部五种。每个原子对象有统一的修改顺序，seq_cst 操作另有共同全序。比较交换失败是读；v0.1.5 允许的（成功→失败）搭配为：relaxed→relaxed；acquire→relaxed/acquire；release→relaxed；acq_rel→relaxed/acquire；seq_cst→relaxed/acquire/seq_cst。volatile 不能替代同步。更完整的原子公理、栅栏及平台支持范围归内存模型和目标附录。

以下从高到低，每行一级；同级在未另行规定时左结合。

```text
调用、下标、成员、可空成员、后缀传播        ()  []  .  ?.  !  ?
前缀                                    !  ~  -  *  &
乘除余                                  *  /  %  *%  *|
加减                                    +  -  +%  -%  +|  -|
移位                                    <<  >>  <<%  <<|
范围                                    ..  ..=
顺序比较                                <  <=  >  >=
相等比较                                ==  !=
位与                                    &
位异或                                  ^
位或                                    |
逻辑与                                  &&
逻辑或                                  ||
可空后备（右结合）                       ??
错误捕获（右结合）                       catch
```

范围及相等运算不能链式组合，顺序比较可按 §7 成链。赋值和更新只在语句层出现。`&name := ptr` 的 `&name` 是局部声明的**绑定模式**，`:=` 不是表达式赋值运算符，故不存在与前缀取地址和二元位与运算的优先级歧义；表达式中的 `&name` 仍按前缀取地址解释。move 与 new 有独立表达式语法；new 的后缀传播作用于分配与构造的整体结果。表达式运算符最长匹配，如 `<<%=`；`move=` 并非运算符。`if` 的无花括号单表达式分支要求整个条件使用圆括号并含 `else`，块分支不要求圆括号；`for` 的三段式与条件/遍历头可选择用一对圆括号包围，解析按匹配层级识别 `;` / `in`。类体同时接受成员 `pub` 修饰和 `public:` / `private:` 段落标签；包级不接受访问标签。在类型位置逐个读取 `?`、`!` 前缀及泛型闭合的 `>`，可解析 `!??T`、`channel.Channel<coll.Vec<u8>>`。表达式中 `??`、`>>` 各为一个运算符。对已识别的泛型名或类型名，完整尖括号实参表后紧跟调用、成员或构造后缀时按实例化解析；编译期值实参中的比较或移位可加括号。条件与字段构造等局部歧义可用括号显式限定。

## 19. 综合示例

本例采用宿主并发库。io.println 在此宿主接口中返回 !void，使输出失败也能沿任务错误通道报告。

```cpp
package main
import (io, task, channel)

enum Work {
    Number(i32),
    Stop,
}

func calculate(n: i32) i32 { n * n }

func main() !void {
    tx, rx := channel.Channel<Work>.bounded(8)!;
    group := task.TaskGroup();

    var produce = [move(tx)]() !void => {
        for n in 0..10 {
            tx.send(Work.Number(n))!;
        }
    };
    var producer = group.spawn<void>(move(produce))!;

    var consume = [move(rx)]() !void => {
        var reader = move(rx);
        for {
            var msg = reader.recv()!;
            switch msg {
                null => break,
                some(Work.Number(n)) => io.println(calculate(n))!,
                some(Work.Stop) => break,
            }
        }
    };
    var consumer = group.spawn<void>(move(consume))!;

    producer.join()!;
    consumer.join()!;
}
```

生产者移入唯一 Sender 顺序发送十条消息。它退出时先释放捕获，因此即使 producer 句柄仍存活，消费者也能排空并观察到 null。若第二次 spawn 失败，启动调用释放已经转入的 Receiver，生产者的等待发送被唤醒；入口传播错误时组仍取消并回收生产者。若输出失败，消费者退出并释放 Receiver，生产者不会永久等待容量；组分别处理已领取及未观察到的任务结果。

## 20. 编译器边界

编译器按词法作用域检查借用，追踪可证明的来源。尚未支持引用字段、保存安全引用的枚举及数组、带引用的元组构造。只读引用可以在表达式中合并来源。合并后同时约束所有可能的所有者，且不能作为带单一来源合同的返回值。不同来源的可写引用仍需分支内使用。引用、裸指针和切片不允许指向含安全引用的槽位。匹配带引用的载荷时，可用 `&x` 访问其目标。无法验证的安全引用组合在编译期拒绝。闭包不支持长期保存安全引用；线程之间不可交付安全引用。动态接口使用统一的引用参数契约，泛型接口方法仍有限制。

容器安全查询借用容器接收者，冲突期间拒绝可变操作。低层 `getPtr`、`getMutPtr`、切片、原始指针迭代器和返回裸地址的运行期守卫仍遵守各自的失效条件。运行期守卫提供的裸地址不得在守卫释放后使用。布局与检查见 [引用实现](reference-implementation-v0.1.4.md)。

## 附录 A．v0.1.5 关键语法（规范性）

本附录规定文件头、主要绑定、`if`、`for` 和枚举模式的必要文法子集。其余表达式优先级、类型构造和成员访问由正文决定。`[]`、`{}` 在元语法中表示可选与重复；引号内是 Vaqrin 的实际词法符号。`Expression`、`Block`、`Declaration`、`Identifier` 等为对应语法类别，不允许 `_` 作为普通标识符。

```ebnf
File             ::= [ PackageHeader ] { ImportHeader } { Declaration }
PackageHeader    ::= 'package' Identifier
ImportHeader     ::= 'import' '(' ImportItem { ',' ImportItem } [ ',' ] ')'
ImportItem       ::= PackagePath [ 'as' Identifier ]
                   | StringLiteral [ 'as' Identifier ]  (* .vqr 文件路径 *)

PostfixPropagation ::= '!' | '?'
BindingItem      ::= Identifier | '&' Identifier | '_'
BindingList      ::= BindingItem { ',' BindingItem }
LocalInfer       ::= BindingList ':=' Expression ';'
LocalVar         ::= 'var' Identifier [ ':' Type ] [ '=' Expression ] ';'
                   | 'var' '&' Identifier '=' Expression ';'
LocalConst       ::= 'const' Identifier [ ':' Type ] '=' Expression ';'
Parameter        ::= [ 'comptime' ] IdentifierList ':' ParamType
ParamType        ::= Type | 'in' '&' 'const' Type
ReferenceType   ::= '&' [ 'const' ] Type

IfBlock          ::= 'if' Expression Block [ 'else' ( Block | IfBlock | IfSingle ) ]
IfSingle         ::= 'if' '(' Expression ')' Expression 'else' Expression
ForStmt          ::= 'for' Block
                   | 'for' ForHead Block
                   | 'for' '(' ForHead ')' Block
ForHead          ::= [ ForInit ] ';' [ Expression ] ';' [ ForUpdate ]
                   | Expression
                   | BindingList 'in' Expression
ReturnStmt       ::= 'return' [ Expression ] ';'

Pattern          ::= '_' | Identifier | 'ref' Identifier | '&' Identifier | 'null'
                   | Literal | ConstructorPattern | TuplePattern
ConstructorPattern ::= QualifiedName [ '(' [ Pattern { ',' Pattern } [ ',' ] ] ')' ]
TuplePattern     ::= '(' Pattern ',' Pattern { ',' Pattern } [ ',' ] ')'
SwitchArm        ::= Pattern { ',' Pattern } '=>' ( Expression | Block )
ClassAccessLabel ::= 'public' ':' | 'private' ':'
ClassMember      ::= [ 'pub' ] Declaration | ClassAccessLabel
```

`PackageHeader` 和 `ImportHeader` 后**没有**分号，且只能处于源文件头部；普通 `Expression` 不能通过换行自动终止。`IfSingle` 的条件必须整体带圆括号并有 `else`，`IfBlock` 的块分支可以带圆括号条件；同一条 if 的两侧直接分支应同为块或表达式。`for` 可以用圆括号包住完整三段式、条件式或遍历式头部，按顶层 `;` / `in` 区分。`ClassAccessLabel` 仅在类成员层合法。`Parameter` 的名字使用普通 `Identifier`，借用权限写在类型处。未初始化的 `LocalVar` 必须使用普通 `Identifier` 和显式非引用类型。

**语法片段示例**（文件头和局部语句分段展示，局部语句必须放在函数或其他允许局部绑定的块内）：

```cpp
package demo
import (coll, io, "shared.vqr" as shared)
```

```cpp
&item := ptr;
var &ro: *const i32 = ptr;
best := if (a > b) a else b;
best2 := if a > b { a } else { b };
for (i := 0; i < n; i++) { work(i); }
```

`if cond expr else expr` 在无块且无圆括号条件时非法；`package demo;`、`import (io);` 非法；`return a, b;` 和 `dst move= src;` 仍非法。

## 附录 B．需要满足的语义判定（规范性）

| 编号 | 场景 | 规范结果 |
|---|---|---|
| S01 | `&x := ptr`，`ptr: *T` | 建立可写 T 位置别名；仅取 ptr 当前地址一次 |
| S02 | `&x := ptr`，`ptr: *const T` | 建立只读 T 位置别名 |
| S03 | `var x: &const T = mutablePtr` | 安全权限收窄；不会恢复可写性 |
| S04 | `&x := pp`，`pp: **T` | x 是 *T 左值，&x 是 **T |

| S07 | `&x := optionalPtr`，`optionalPtr: ?*T` | 编译错误：不能隐式处理可空层 |
| S08 | `&x := resultPtr`，`resultPtr: !*T` | 编译错误：不能隐式处理错误层 |
| S09 | `&x := ptr; ptr = other;` | x 保持最初地址，不重绑定 |
| S10 | `&x := ptr; move(x)` | 编译错误：别名不是拥有型变量 |
| S11 | `func f(&x: *T)` 与 `func f(p: *T)` | 前者为非法的旧语法 |

| S19 | `switch move(value) { Tag(ref x) ... }` | x 借用匹配器拥有的存储，分支退出清理未交付部分 |

| S24 | `[&x]` 捕获已绑定别名 x | 安全引用捕获暂不支持；可按值捕获其可复制目标 |
| S25 | 通过悬垂 `&x` 地址访问 | 沿用普通裸指针 UB；语法不提供自动寿命延长 |
| S26 | `return (a, b)` 返回 `(A,B)` | 合法元组表达式，既有所有权规则继续适用 |

| S30 | `for i := 0; i < 10; i++ {}` | 合法；++ 仅为语句及更新缩写 |
| S31 | `for (i := 0; i < 10; i++) {}` | 合法；与无附加括号的三段式具有相同语义 |
| S32 | `x = move(y);` | 合法移动赋值，移动源约束不变 |
| S33 | `x move= y;` | v0.1.5 语法错误 |

## 附录 C．保留语法与取舍记录（解释性）

v0.1.5 的裁定是**保留有实用价值的并行语法，不为了追求形式上的唯一拼写取消现有能力**。`pub` 逐项修饰与 `public:` / `private:` 分段标签服务不同的代码组织习惯；它们能由上述默认权限与显式覆盖规则稳定并存。`if` 的块和单表达式形式同样保留，后者只要求圆括号条件以消歧。计数循环的带括号和不带括号头完全同义，解析用顶层分号区分；其重复不改变语义或增加新的控制流能力。

| 领域 | 正式保留 | 仍然移除/限制 | 决策依据 |
|---|---|---|---|
| 文件头 | `package name`、`import (...)`，两者没有分号；package 可省 | 头部末尾 `;` | 文件头指令有清晰语法结束，避免多余分号 |
| 小程序 | 每文件独立 main、同目录自动发现普通函数、目录选主文件 | 同一可执行目标中自动混入多份 main | 允许在一个目录保存独立习题与小程序 |
| 访问控制 | `pub` 与类体 `public:` / `private:` | 在包级使用段落标签 | 单项修饰和分段布局共存，优先级明确 |
| if | `if cond { ... } else { ... }` 和 `if (cond) expr else expr` | `if cond expr else expr` | 块分支与表达式分支都直观且可确定解析 |
| for | 带/不带圆括号的完整计数/条件/遍历头 | 不完整的分隔符和歧义头 | 传统习惯与简洁写法都可用 |
| 元组返回 | `return (a, b)` | `return a, b` 特殊简写 | 只有一个元组表达式构造规则 |
| 移动赋值 | `dest = move(src)` | `dest move= src` | 已有显式移动操作，无需第二种赋值运算符 |
| 引用 | `var &x = ptr`、`&x := ptr`、`var x: &T = ptr` | 带类型的旧别名及参数别名语法 | 类型身份和访问语义一致 |
| 不返回类型 | `never` | 不完整的内部 Never 拼写 | 公开标准包签名可精确定义 |

## 附录 D．面向多 main 小程序的规范示例（解释性）

下列目录既能直接编译其中任一文件，也能以目录和配置指定默认目标：

```text
scratch/
  hello.vqr
  sort.vqr
  helpers.vqr
  package.toml   # 可选；当目录中有多个 main 而要求直接编译目录时使用
```

`helpers.vqr` 没有 package，也没有 main；即使不写 pub，其功能仍可被同目录其他匿名文件发现：

```cpp
func twice(n: i32) i32 { n * 2 }
```

`hello.vqr`：

```cpp
import (io)

func main() !void {
    io.println(twice(21))!; // 同目录唯一符号，自动发现 helpers.vqr
}
```

`sort.vqr`：

```cpp
import (io)

func main() !void {
    io.println("sort demo")!;
}
```

两份 `main` 允许并存。`vaqc build scratch/hello.vqr` 编译 `hello` 的入口及其调用的 helper，而不会编译 `sort` 的入口；`vaqc build scratch/` 在无配置时因两个候选入口而给出明确错误。设置目录内 `package.toml`：

```toml
[package]
name = "scratch"
version = "0.1.0"

[build]
entry = "hello.vqr"
```

此后 `vaqc build scratch/` 以 `hello.vqr` 为默认目标；也可以临时指定 `vaqc build scratch/ --entry sort.vqr`。`[package] name` 只标记项目，不将匿名源文件强制合成一个共享名字空间。若同目录 `demo-a.vqr` 与 `demo-b.vqr` 都声明 `package demo` 并各有 `main`，则 `vaqc build demo-a.vqr` 与 `vaqc build demo-b.vqr` 分别选择不同的文件私有入口，但它们仍共享除 main 以外的包级声明。
