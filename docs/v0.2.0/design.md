# Vaqrin v0.2.0 语言设计

目标规范。发布版本与实现状态见 [实施记录](implementation-plan.md)。未在本分支验收的语义以此为设计目标。

## 值、参数和存储位置

`T` 是数据类型。函数参数的模式参与源语言签名、泛型实例、接口匹配与间接调用。参数从左到右求值。

| 签名 | 调用 | 函数内部 |
| --- | --- | --- |
| `x: T` | 需要 Copyable。现有值使用其 Copy 操作，临时值可直接初始化副本 | 可写的独立副本 |
| `x: in T` | 共享借用匹配类型的可读位置或物化临时值 | 只读，禁止移动 |
| `x: mut T` | 独占借用匹配类型的可写位置，临时值无法满足 | 可读和替换目标，禁止移出 |
| `x: move T` | 需要非 Copyable 且 Movable。具名对象须显式移动，临时所有者可交付 | 可写、可析构、可再移动 |

普通数据位置可直接借用。安全引用按目标类型重借用，允许从可变缩窄到只读。精确匹配引用类型优先，例如只读引用句柄可以作为 Copyable 数据按值传递。指针和 Box 作为对象时具有各自的类型。要把其目标传给期望目标类型的函数，调用点必须写 `*p` 或 `*box`。泛型可推导指针对象自身的类型，永远不会凭指针或 Box 的形状猜测其目标类型。

借用模式的泛型推导先看实参的目标位置类型。若形参的具体类型已经确定，则按其精确匹配规则处理。Value 模式的类型参数须有 Copyable 约束。Move 模式在实例化时验证非 Copyable 和 Movable。不同参数模式参与函数类型身份，不能用类型转换改变调用契约。仅靠参数模式差异形成的同名重载将被拒绝。

## 权限、引用与生命周期

- `ref T` 表示共享借用，`ref mut T` 表示独占借用。声明和模式中的 `ref` 与 `ref mut` 借用相应位置，创建借用必须拥有相应的访问权限。
- `raw place` 取得原始指针。可变位置产生 `*T`，只读位置产生 `*const T`。从安全引用取得原始指针须通过 `toRaw()` 显式操作。
- 裸指针须在 `unsafe` 中显式解引用。访问目标的字段或方法时写 `(*p).member`。裸指针的有效性、对齐、初始化与排他性由调用方保证。Box 仍写作 `^T`，使用显式、安全的 `*box`。
- `&` 保留为位与及复合位与的一部分。Trait 交集写作 `T: Comparable + Copyable`。
- 每个借用记录来源、权限、区域和重借用的父节点。共享借用可并存，可变借用必须排他。移动、覆盖和结构性修改须验证活动借用。分支合并使用所有可能来源，无法证明互不重叠的索引保守视为别名。
- 所有权转移只针对完整所有者。引用、指针或 Box 的解引用结果不可移动。消费 Box 取出载荷须显式调用 `intoInner()`。
- 借用存储的区域随来源传播。引用字段与容器元素须使用可追踪的来源，直到区域关系能被证明为止。泛型聚合类型的区域由各借用字段的来源推导，函数边界由签名声明来源。

持有共享引用的局部元组分别追踪引用载荷及元组自身的存储。直接借用具体的标量槽位时，槽位的来源是元组局部变量而非载荷引用所指的对象。不同标量槽位可以分别借用；整个元组的访问仍须遵守槽位上的借用。当前只为可证明的直接局部投影建立这个槽位借用，不允许借整个含引用元组来取得可写权限。

闭包 `[a, ref b, ref mut c, move(d)]` 依次复制、共享借用、独占借用和接收所有权。需要借用字段时，可先用 `ref` 或 `ref mut` 把字段绑定到名字，再捕获该名字。各捕获独立记录来源和权限；不相交的字段可以同时借用，同一位置上的排他冲突会被拒绝。捕获不会延长所有者的寿命。含独占捕获的闭包不能复制，不同独占来源在控制流汇合时也不会合并。含借用的闭包不接收携带未追踪指针或视图的拥有捕获。延迟调用可以保留已检查且活到清理时的显式引用捕获。含独占捕获的闭包在登记时保留独占调用权限，不能再次调用或登记；不修改环境的共享闭包可多次登记。

返回引用只有一个借用参数时隐式使用该参数。选择多个可能来源中的一个时写 `from name`，方法可写 `from self`。只读来源只能产生只读返回值。对于函数类型，使用有名形参表达显式来源。包装返回类型中的引用继承相同来源。调用结果可以暂时借用实参临时对象直到完整表达式结束。把该引用存入更长寿命的位置必须拒绝。按值传入的引用描述符、聚合以及 `move` 参数不能作为返回借用来源；需要写 `in` 或 `mut`。已绑定且可复制的只读引用聚合可按 `in` 借用；不要借用它的临时副本。

分阶段实现：显式 `from` 可用于 `str` 或标量元素的只读切片 `[]const T`。来源限定为持有存储的 `in` 参数或 `const` 方法的 `self`；必须从已知存储形成视图，不能把裸指针或旧式视图直接声明为已检查来源。一层可空只读视图 `?str` 与标量只读切片 `?[]const T` 也可声明返回来源。已知为 `null` 的分支不需要所有者；调用结果在静态检查中保守地视为可能有载荷。用 `some` 包装、解包、模式匹配或 `??` 都不消除借用；不能将已检查视图与未追踪的非空视图合并。绑定已检查的视图会保留共享借用，所在作用域结束前不能移动或覆盖所有者。临时所有者只允许在当前完整表达式内读取。除上述一层可空只读视图外，未建立生命周期追踪的聚合、包装、闭包、参数和返回位置暂不接收已检查视图。普通 `str`、切片、迭代器和标准库签名不因此自动获得生命周期保证。

`ref view[index]` 可借用受检只读切片的元素，并继承底层存储的来源和生命周期。下标按可能重叠处理，借用期间保护所属存储，临时所有者仍受完整表达式边界限制。形参 `in []const T` 也可接收普通切片描述符，因此单凭该形参无法证明底层存储的来源。来自这种形参的下标投影可读取，建立元素引用须有独立的存储来源证明。

`in str` 和标量元素的 `in []const T` 可作为已检查视图的非逃逸参数，仅借用到调用结束。编译器检查参数不能流入旧式按值接口、存储或未经检查的返回位置；不能登记为延迟调用的参数，也不能用作视图返回的拥有者。上下文中的字符串字面量和从拥有字符串形成的只读视图不复制字节。

## 语句、清理与错误

条件和循环体均为块。范围循环与三段式循环使用 `for`，条件循环使用 `while`，无条件循环可写 `for {}`。循环头不加外层圆括号，表达式内部仍可用圆括号分组。标签只绑定词法内的循环，带标签退出经过所有被离开的作用域。 `for ref item in values` 和 `for ref mut item in values` 分别创建只读和独占的元素借用；借用不得逃出当次迭代。数据来源可以是可证明所有权的命名定长数组，或其整个局部存储槽的已检查别名；共享形式也支持已检查来源的命名只读标量切片（如 `from` 返回值或 `in []const T` 形参）。动态下标的冲突检查保守地覆盖该存储来源。普通未追踪切片和迭代器返回的裸指针不会自动变成安全引用。

`if let` 使用 `switch` 的模式规则，绑定只在成功分支中存在。普通语句以分号结束，块尾表达式产生块的值，包头和导入可选分号。类成员默认私有，以声明级 `pub` 标记公开成员。值构造使用 `T(args)`，堆构造使用 `new T(args)!`。定长数组和元组仍有自己的字面量。类的字段初始化由内部 `init` 管理。 所有类均不接受空花括号 `T{}`；无字段且未声明构造器的类型可用值构造 `T()` 进行空初始化，堆构造仍要求声明 `init`。已声明的 `init` 仍参与匹配和访问检查。非空具名字段构造仍是待迁移的旧形式。

`defer call(...)` 在注册时求值函数、接收者和参数，保留至退出时执行。延迟块按登记处的词法作用域捕获被引用的外部绑定，而不是复制值。只读访问保留共享借用；写入保留独占借用。捕获须已初始化且活到清理执行，不能从捕获移出所有者。当前实现对捕获按整个根绑定保留借用。按逆注册顺序清理，适用于正常退出及所有恢复性非局部控制流。要求清理体显式处理错误，禁止在清理体内改变原返回或原错误路径。trap 和进程终止不保证清理。清理动作与析构均按逆注册顺序执行。

对返回 `!void` 的清理函数，使用延迟块显式处理错误：

```vaqrin
defer {
    file.close() catch (reason) { reportCloseFailure(reason); };
}
```

不要写 `defer file.close();` 丢弃错误，也不要在延迟体中用 `!` 或 `?` 传播到外层。当前延迟块中，错误结果须处理后再绑定成功值。块内自己的循环仍可跳转。


`!T` 是错误结果，`?T` 是可空值。`expr!` 只传播错误，`expr?` 只传播空值。`!?T` 的三种状态分别是错误、成功为空、有值，`?!T` 的最外层为空时独立于内部错误。签名（包括函数类型、lambda）和字段（包括枚举载荷）中不能直写连续包装，括号分组不会改变这一规则。用具名别名表示复合包装，例如 `type Lookup<T> = !?T;`，其类型与展开后完全相同；标准库提供 `core.ResultOptional<T>`、`core.OptionalResult<T>` 和 `core.NestedOptional<T>`。单个类型表达式最多写两个连续包装，需要更深层次时组合别名。后缀按从左到右的顺序逐层解包。保留 `??` 和 `?.`。`catch` 的错误绑定只在处理表达式内生效，表达式尾值成为后备结果，`return` 始终退出所在函数。

## 整数

普通运算保持具体整数的位宽与符号。未定型常量可按期望类型检查并适配，两个不同的具体整数类型必须显式转换。普通加减乘在 Debug 和 Release 都检查有符号和无符号溢出，复合赋值采用相同规则。`+%`、`-%`、`*%` 显式回绕。移位计数必须非负且小于左操作数位宽。普通左移检查结果范围，`<<%` 显式舍弃移出的高位。饱和运算使用 `num.saturatingAdd`、`num.saturatingSub` 或 `num.saturatingMul`。缩窄转换返回可检查结果。需要保留低位并丢弃高位时使用 `convert.truncBits<T, U>`，目标整数必须比源整数窄。

## 模块入口

`vaqc run file.vqr` 构建并运行唯一的显式单文件入口。目录构建以目录为包，无隐式兄弟文件别名。多文件共享同一命名包，可通过导入组合其他包。多个二进制入口须由 `--entry package::main` 或项目清单 `[build].entry = "package::main"` 明确选择；导入使用逻辑包名，不接受源文件路径。C ABI 使用既有显式 ABI 标记和原始指针。

## 核心语法摘录

```ebnf
parameter        = identifier ":" [ "in" | "mut" | "move" ] type ;
reference-type   = "ref" [ "mut" ] type ;
borrow-expression = "ref" [ "mut" ] place ;
raw-expression   = "raw" place ;
reference-binding = "ref" [ "mut" ] identifier "=" place ";" ;
borrow-result    = type [ "from" (identifier | "self") ] ;
constraint       = trait { "+" trait } ;
defer-statement  = "defer" (call ";" | block) ;
labeled-loop     = [ identifier ":" ] (for-loop | while-loop) ;
```
