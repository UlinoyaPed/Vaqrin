# Vaqrin v0.2.0 语言规范草案

**状态：目标规范，尚未发布。** 本文规定 v0.2.0 拟交付的源语言语义。配套的 [完整源语法](grammar.ebnf) 不把兼容解析器接受的旧拼写列作规范。文末另列基于开发快照 `3f4d6e8` 的实现边界。现行发布规范和版本号不因本文改变。

## 1. 适用范围

Vaqrin 是原生编译、静态强类型、采用值语义及 RAII 的系统语言。源码扩展名为 `.vqr`，编译器命令为 `vaqc`。**必须拒绝**表示编译错误；**trap** 表示规定的不可恢复运行时检查失败；**未定义行为**表示违反了由调用者承担的底层前提。类型检查、程序行为、ABI 和库 API 的兼容性不由语法版本单独保证。v0 期间允许破坏性迁移；自 v1 起，同一主版本的语法兼容承诺按版本政策执行。

本文描述源语言及与其语义直接相关的库边界，不把某个 LLVM lowering、二进制布局或实现上的保守拒绝规定为永久接口。平台与独立编译约束见 [平台说明](../platforms.md)。未在本文替换的既有字面量值、标准类型、编译期求值、宿主 ABI 与运行时约定以 [上一版对应条款](../language-spec-v0.1.5.md) 为起点，不能借此恢复被本版删除的语法或绕过本版所有权规则。

## 2. 源文件及名字

源文件使用 UTF-8。标识符使用 Unicode XID 起始及后续字符，允许下划线起首，区分大小写，按 NFC 规范化后的拼写比较；字符串内容不进行该正规化。单独的 `_` 是忽略项或数组长度推断标记。整数支持十进制与 `0b`、`0o`、`0x`，可带位宽后缀及数字分隔下划线；浮点字面量可写带小数或指数的十进制数。无上下文的整数及浮点字面量分别默认 `i32`、`f64`。字符是单个 Unicode 标量，双引号文本是 UTF-8 字符串；文本的标量不是字节长度。注释有 `//` 和不嵌套的 `/* ... */`。

文件头按顺序是至多一个 `package Name`，随后是零个或多个 `import (path, path as alias)`。头指令后可有分号；这不是通用自动分号插入。普通声明、绑定、赋值和非块尾表达式语句须以分号结束；结构性块不需末尾分号。块尾表达式无分号时给出该块的值；有分号的表达式作为语句执行，不能以丢弃尚未处理的错误结果代替处理。

类成员默认私有；`pub` 只对紧随的声明生效。不使用 `public:` 或 `private:` 段落。包内跨文件可访问本包普通声明；跨包需公开且显式导入。类仅通过组合及接口复用，不采用传统继承；`embed` 不把字段隐式提升。属性如 `#implements: Speaker` 用于声明契约，不改变默认可见性。属性的目标和内容应在声明处校验。

## 3. 类型、所有者、位置及绑定

`bool`、`char`、`iN`、`uN`、`isize`、`usize`、浮点类型、`void` 与 `never` 是基础类型；`never` 无正常完成路径。类、枚举和接口具有声明身份。别名透明，不派生新的类型身份。定长数组 `[N]T`、推断长度的数组字面量 `[_]T{...}`、元组 `(A, B)`、切片 `[]T` / `[]const T`、拥有型字符串 `string` 与只读视图 `str` 表达不同的存储与权限。下标必须在范围内；元组位置参与类型身份。

绑定可写作 `var name: T`、`var name = value`、`const name = value`、`comptime const name = value` 或 `name := value`。普通 `const` 只限制赋值，并不要求编译期求值。读取或借用一个位置前必须证明它在所有可达前驱上已初始化。**位置**表示现有存储，包括局部绑定、有效对象的字段与下标投影，以及合法解引用。赋值更新已有位置，不创建所有者别名；替换拥有值时，旧值须恰当析构，不能覆盖还在活动借用下的存储。

`Copyable` 值可复制；普通隐式复制不可失败。需要分配或可能失败的复制必须通过显式可检查接口。只有拥有整个对象且满足 `Movable` 的调用者可以转移所有权。移动后的源位置失去初始化状态，在重新初始化前不可读取或借用；不支持部分移动，不得从引用、裸指针或 Box 的解引用结果移出。非拥有视图不因复制其句柄而延长存储寿命。

用户构造类值用 `T(args)`；独占堆分配用 `new T(args)!`。类内部 `init` 完成字段初始化，不作为普通方法调用；构造失败清理已成功取得的所有权。数组与元组有自己的字面量，不是类的第二套公开构造语法。析构由编译器按存储所有权执行，移动不造成双重析构。组合字段的初始化、析构和公开性均遵守它自己的声明。

## 4. 原始指针、Box、安全引用及别名

- `*T`、`*const T` 表示可写、只读裸指针；裸指针不拥有目标。空性应写成可空指针而非把空地址当合法目标。`raw place` 仅取得地址，可写位置产生 `*T`，只读位置产生 `*const T`；它不建立安全借用。安全引用转为裸指针须显式调用 `toRaw()`，不能通过 `raw alias` 规避。
- `*` 还作乘法和显式解引用。规范不允许通过裸指针或 Box 隐式访问被指对象。裸指针解引用及作用等价的访问必须置于 `unsafe`，调用方保证有效性、对齐、初始化、关联期间的别名权限及无数据竞争；`unsafe` 不把错误或未验证的指针变为安全引用。
- `^T` 是独占拥有、可移动且不可按位复制的 Box。`*box` 是针对已初始化 Box 所有者的显式、安全借用位置；消费 Box 取出载荷须写 `intoInner()`，不能写 `move(*box)`。
- `ref T` 是共享只读借用，`ref mut T` 是独占可写借用。`ref place` 或 `ref mut place` 创建相应借用；`ref name = place;` 和 `ref mut name = place;` 声明借用别名。模式、迭代和捕获可表达同样的权限。共享借用可共存；独占借用排除重叠访问。可从独占权限重借用或缩窄为共享，不得从共享提升为可写。重借用不超过父借用的权限或寿命。
- 借用必须可证明来源和有效区间。保守合并分支的所有可能来源，不能仅检查其中一个来源。`mut` 借用已知不同字段可共存；不能证明不同的动态索引视为重叠。移走、覆盖、重新分配或结构修改活跃借用的所有者必须拒绝。
- 区域关系随聚合、引用字段、容器项目、返回值、闭包及迭代器传播。若无法证明来源存活或某次操作不使引用失效，必须拒绝。借用不隐式延长来源存储期。这里的允许条件是规范目标，不意味着开发版接受所有可证明的形态。
- 开发版的 `Vec<T>.borrowSlice()` 为整数、浮点数、`bool`、`char` 提供带 `from self` 的只读切片。持有视图期间，禁止移动或修改 Vec，包括扩容和删除；子切片仍保护同一所有者。可索引、按共享引用迭代，或传给受检查的 `in []const T`，不能传给按值接收普通切片的函数。来自临时 Vec 的视图只在当前完整表达式可用。Vec 的普通 `asSlice`／`asConstSlice` 还没有这一契约，不可当作已迁移的安全接口。线性代数的 `Vector<T>.asSlice()` 和 `Matrix<T>.asSlice()` 转发受检查的只读标量切片；`dot`、`norm2`、`normInf`、`distance` 和 `outer` 用 `in []const T` 读取，不取得存储所有权。可空行视图与可写切片暂未迁移。
- 开发版的 `#borrowed: scoped` 类允许静态工厂和只读实例方法，不允许引用字段重绑定、析构器或自定义复制。实例方法直接调用必须使用已经绑定的完整接收者；不支持延迟调用。迭代协议生成的隐式绑定也保留迭代器借用，直到退出循环。

## 5. 函数、参数模式和泛型

参数模式与数据类型共同决定源语言签名，包括接口匹配、特化、函数值及间接调用。仅改变参数模式不能形成同名有效重载。求值顺序是函数值或接收者在前，参数从左到右；后续实参不得使已经计算出的地址或借用失效。

| 形参 | 所需实参 | 被调用者权限 |
| --- | --- | --- |
| `x: T` | `T: Copyable`；现有值按规则复制，可直接初始化临时副本 | 独立可写副本 |
| `x: in T` | 可读位置、安全重借用，或允许物化的调用临时值 | 共享读取，不可写、不可移出 |
| `x: mut T` | 现有可写位置或合法可写重借用 | 排他读取、修改或替换；不能移出 |
| `x: move T` | 非 Copyable、Movable 的完整所有者；具名值写 `move(value)`，新拥有临时值可直接交付 | 成为所有者，可替换、析构、再移动 |

实参与形参类型精确匹配时优先按精确类型处理。例如只读引用值本身可以是 Copyable 实参；在要求目标对象的借用模式中才考察安全引用的目标。不能因参数或泛型形状自动解引用指针或 Box；确需目标时写 `*p` 或 `*box`。泛型 Value 在定义和可调用实例中必须具有足够的 Copyable 保证；Move 校验非 Copyable 与 Movable。Trait 交集写作 `T: A + B`，不是位与。编译期参数和值受其声明约束；不支持的编译期副作用应拒绝。

返回借用的来源来自实际输入：唯一符合的 `in` / `mut` 来源可隐含；多个来源中明确选择时写 `from name`；方法可写 `from self`。函数类型用具名形参配合 `from`，不能借此更换调用契约。包装的返回引用使用相同来源。共享来源不能返回独占引用；局部、临时或未经证明来源不得逃逸。调用点实参的合规临时借用可供当前完整表达式消费，不能保存到更长寿命位置。

Lambda 用 `name => expression` 或带形参表的 `(x: T) U => body`。显式捕获列表支持复制 `[value]`、借用 `[ref value]` / `[ref mut value]` 和转移 `[move(value)]`。借用捕获将来源及权限带入闭包，存活不能超出来源；把闭包作为值复制或移动不能改变其借用契约。消费拥有捕获的闭包不能据此被反复调用。

## 6. 控制流、匹配和迭代

`if condition { ... }`、`if let pattern = expression { ... }` 及 `else { ... }` 使用块；允许 `else if`。没有单表达式分支。匹配发生时 `if let` 的新绑定仅在成功分支内有效。作为有值表达式时，各正常完成分支的类型必须相容；不能让缺少分支的路径伪造值。

循环写作 `while condition { ... }`、`for item in values { ... }`、`for init; condition; step { ... }` 或 `for { ... }`。不把整个循环头套在括号里，不写条件式 `for condition`；表达式子项仍可分组。标签 `outer: for ...` / `outer: while ...` 绑定词法内的循环，可被其内部的 `break outer` / `continue outer` 使用。跳转清理每个被离开的作用域。范围运算 `..`、`..=` 分别表示上界排除与包含。

`for ref x in items` 和 `for ref mut x in items` 分别建立共享和排他元素借用。元素借用受相应迭代及集合存储区间限制，不得逃出该次迭代。规范不把实际返回裸指针的迭代器隐式变成安全引用。

`switch expression { pattern => body, ... }` 支持枚举载荷、可空值、元组和值模式，支持 `_`、`else` 和同臂备选模式。参考语法的 `some(...)` / `null` 和枚举名表示相应构造形态。借用模式 `ref x` / `ref mut x` 绑定实际载荷槽及对应权限，而不是隐式解引用载荷里的裸指针。备选模式绑定集及权限必须一致；有值匹配须覆盖其可能域。普通绑定不能以匹配为由擅自移走借用中的资源。

## 7. 错误、缺失和清理

`!T` 是 `T` 或错误标识，`?T` 是有值或空。二者互不等价，顺序也不可交换。成功为空、成功有值、失败是 `!?T` 的独立可观察状态；`?!T` 的外层空不等于内层错误。签名、函数类型、lambda 签名及字段（含枚举载荷）中不得直写连续包装，括号分组不隐藏包装。别名定义可写至多两层连续包装；更深层通过别名组合。例如：

```vaqrin
type Lookup<T> = !?T;
type DeferredLookup<T> = ?Lookup<T>;
func lookup(value: i32) Lookup<i32> {
    if value == 0 { return null; }
    some(value)
}
```

后缀 `expr!` 传播外层错误，`expr?` 传播外层缺失；从左到右逐层应用，每一步须有对应的外层及可传播的返回通道。`a ?? fallback` 仅在空时求后备值。`a?.member` 对空跳过访问，对存在值作条件访问。没有相容缺失通道时，使用分支或后备表达式显式处理，而不是把缺失自动映射成错误。

`expr catch (reason) { ... }` 在失败路上执行，`reason` 只在处理器内有效；可使用不带绑定的 `catch`。处理器的正常块尾值是后备结果。在处理器中执行 `return` 退出整个所在函数，不是从处理器返回的局部替代语法。未执行路径的后备不得求值。

`defer f(args);` 注册时求值函数、接收者和参数，退出时调用。`defer { ... }` 捕获其实际使用的外层词法绑定，可读借用与独占借用按访问需求建立；捕获须已初始化且持续有效，不能从被捕获的借用移出所有权。清理动作和析构按注册逆序混合执行。正常退出、显式返回、`!` / `?` 传播与跨作用域循环跳转必须执行被离开作用域的清理。已决定的返回值或传播通道不得被清理体覆盖。清理错误须显式处理；不应把失败调用直接注册为无返回值的延迟调用。示例：

```vaqrin
defer {
    file.close() catch (reason) { reportCloseFailure(reason); };
}
```

trap、进程强制终止或未定义行为没有正常栈展开保证。延迟体自身的局部循环可跳转，不得跳出清理体或向外传播失败。

## 8. 运算与转换

整数运算保留具体位宽和符号，没有 C 式整型提升。未确定类型的字面量允许按预期类型选择，但两个具体整数类型的混算必须显式转换。普通整数加减乘及对应复合赋值检查有符号和无符号溢出，不能在优化构建中默默变成回绕。除零、溢出的有符号除法、越界移位与不能表示的受检左移必须诊断或触发 trap，包括负移位量及大于等于左值位宽的移位量。

`+%`、`-%`、`*%` 与 `<<%` 以及其赋值式显式回绕或丢弃移出的高位。整数饱和通过 `num.saturatingAdd`、`num.saturatingSub`、`num.saturatingMul` 等命名 API，而非饱和算符。窄化可用检查型转换；只保留低位的意图用 `convert.truncBits<T, U>`，目标必须比源类型窄。布尔、位、算术、比较、范围、包装及短路运算的优先级见 [EBNF](grammar.ebnf)。`&` 是位与，`&&` 是短路逻辑与；不再用作取地址或引用标记。用户类型可为普通二元算术或比较声明适用的运算符方法，不能重载赋值、短路、移动、取地址、包装传播或清理来绕过这些规则。

## 9. 包、入口、外部接口及工具

`vaqc run file.vqr` 明确构建并运行所选源文件。目录构建以包为组织单位，同包文件共享声明，不依靠兄弟文件名形成隐式模块，也不把同目录所有文件自动当作独立入口。跨包按逻辑包名导入，可保留清单中的路径依赖；不接受引用源文件路径的带引号导入。存在多个目标入口时，用 `--entry package::main` 或 `package.toml` 的 `[build].entry = "package::main"` 明确选择，不按目录枚举顺序猜测。命令行显式入口优先于清单。宿主的 `main` 文件私有、无形参或泛型；库、对象与语法检查不要求宿主入口。

与 C 交互使用显式 `extern "C"` / `export "C"`、受支持的 C ABI 布局和原始指针；安全借用不因 FFI 得到额外保证。任务、Channel 和同步设施依目标运行时能力提供；共享对象与消息交付遵守对应权限及 trait 边界。语法中可写 `select`，并不承诺所有宿主和裸机配置有相同运行时能力。

编译器、LLVM lowering、runtime、格式化、语言服务器、生成器和缓存必须以同一版本的语义拒绝或接受程序。发布前须固定同一个提交，在 Debug 与 Release 运行正例、负例、兼容性边界、示例、安装、编辑器、生成代码和冷/热性能回归。API 约定统一采用 PascalCase 类型名，以及一致的存取、迭代与资源契约；标准库不能要求用户靠隐式裸指针操作取得本应安全的结果。

## 10. 综合示例

以下单文件程序展示限定范围内的共享借用、`mut` 参数、具名包装和延迟清理。它使用显式导入，可以用 `vaqc run demo.vqr` 运行。

```vaqrin
package demo;
import (io);

type Lookup<T> = !?T;
func search(value: i32) Lookup<i32> {
    if value < 0 { return null; }
    some(value)
}

func increment(value: mut i32) void { value++; }
func report(value: i32) void { io.println(value) catch { panic("cannot report"); }; }

func main() !void {
    var n = 40;
    {
        ref shared = n;
        io.println(shared)!;
    }
    increment(n);
    defer report(n);
    if let some(found) = search(n)! {
        io.println(found + 1)!;
    }
}
```

输出依次为 `40`、`42`、`41`。最后一行来自按退出顺序执行的延迟调用。

| 参数与泛型 | 新参数模式有语义检查并参与函数类型及实例匹配，但各调用边界的通用 Copyable 要求、Move/接口推导、旧标准库 by-value 放行仍需全面统一；少量已通过的类型用例不是所有组合的证明。 |
| 借用和视图 | 有根及投影、共享来源集合、完整表达式临时和若干可证明的返回/捕获场景。尚无完整的逐路径区域、回边、任意引用聚合/跨过程及迭代器模型；不承诺非词法借用结束。现有 `for ref` 限于可证明来源的定长数组，新借用迭代不代表所有容器已支持。 |
| 裸指针及 Box | 仍有旧指针或 Box 成员访问的隐式解引用及未统一受 `unsafe` 检查的路径。不得据此承诺普通代码中解引用安全；标准库和 C ABI 边界仍需迁移。 |
| 标准库 | 已检查的只读视图可在受限场景使用显式 `from`，含 Token 及部分输入解析；普通 `str`、切片、迭代器没有自动升级到完整区域系统。容器失效、文件/锁守卫、完整 `get/getMut/iterRef/iterMut` 契约及全库 API 迁移尚未完成。 |
| 清理 | 支持延迟调用及捕获型块，已有再借用和错误处理验收。现有块捕获的权限保守保留整个根；不能把支持部分形态扩展解释为任意原始地址、借用视图或复合捕获都能安全延迟。 |
| 发布 | [迁移对照](breaking-changes.md)、[实施记录](implementation-plan.md) 与 [审计](audit.md) 都不是发布声明。最终规范、工具和 API 对照要在同一最终提交通过矩阵后定稿。 |

`grammar.ebnf` 中的静态限制不靠上下文无关文法表达；例如 `place` 的权限、有效区域、重载是否唯一、包名查找、引用的来源以及包装是否合法都须另行验证。
