# Protobuf

`Reader.open(input, DecodeLimits())` walks a Protobuf binary message.
`next()` returns a field, end of input, or a decoding error. A field exposes
its number and wire type plus checked accessors for the numeric, enum, text
and byte types. Readers, packed readers and field views borrow the original
input. Keep it live and immutable while using them. `asString()` validates
UTF-8 and returns an owned string. `Field.raw()` includes the complete
original encoding, including the end tag of an unknown legacy group.

`Writer(maxBytes)` accumulates fields in a bounded buffer.
`takeBytes()` transfers ownership and leaves an empty writer.
`written()` borrows the writer's buffer until the next mutation. To append
previously written data to that same writer, keep the data in a separate owned
buffer. Use `writeUnknown` to retain an unrecognized field byte-for-byte, or
drop the `Field` to skip it. Read the same primitive encodings via
`PackedReader` for length-delimited packed values and write them via
`PackedWriter`. An empty packed field is omitted.

`Codec<T>` constructs a default value, encodes it, and merges fields into a
mutable value. Use `mergeMessage` on an existing submessage to preserve fields
across repeated singular message occurrences. In a schema codec, singular
scalars take the final occurrence, elements of repeated fields append in wire
order, and repeated map entries replace the previous value for the same key.
Maps use embedded key/value messages. Oneof and optional presence are
decided by which tags the codec reads and writes. Numeric enum values remain
`i32` so that open proto3 enumerations can retain future values.

Decode limits default to 16 MiB per input buffer and 64 levels. Embedded
messages and legacy groups consume the depth budget. Up to 128 levels may
be configured. The wire reader recognizes all six wire types and bounds
varint, tag and length values. It accepts non-minimal value varints and
encodes primitive values minimally. Schema code owns field presence,
duplicate handling, unknown-field storage and per-field policies.

The acceptance fixture tests this API with code generated by the official
Protobuf compiler via Python's `grpcio-tools`. It compares canonical
encoding and checks cross-language decoding, merged messages, presence,
map keys, oneof selection, packed and unpacked values, and unknown groups.
